# ファイル公開経路の監査

## 判定

thumbnail と seek tiles が canonical media file を直接 `O_TRUNC` で開く問題を修正した。
両方をジョブ固有 scratch と共通の stage → lock → transaction → rename → fsync → commit 手順へ変更した。
catalog は世代 directory の予約を原子的な `Mkdir` に変えた。
別 export が書き込み途中の世代を prune しないよう、不完全世代を 7 日保持する。

表の「row」は公開判定に使う DB 行、「予約」は未 commit transaction 内での一意パス確保を指す。
storage contract の不変条件 3 は row と file の組を commit 時点で公開する。
9 は派生判定を commit transaction 内で再確認する。
12 / 13 は派生状態を、その状態を書く worker の media asset row に置くことを確認した。

## 経路ごとの監査

| 経路 | ファイル出力と一時領域 | 直列化と公開点 | 判定 |
|---|---|---|---|
| ingest | mirakc の転送を同じ directory の record 固有 `.rokuban-ingest-` temp に逐次書きする。再開は同じ record の temp に追記する。 | rel_path filesystem lock と transaction advisory lock の下で active row を予約し、temp を rename、親 directory を fsync してから commit する。canonical を転送中に開かない。 | 安全。既存の契約どおり。 |
| encode 本体・字幕 | ffmpeg は job ID 固有 scratch に出力する。完成物は同じ canonical directory の `.rokuban-encode-` stage にコピーする。 | rel_path lock、transaction、advisory xact lock の下で計画と active 状態を読み直す。字幕と本体を rename し、親 directory を fsync してから media asset を upsert、commit する。ジョブ lock を ffmpeg の排他とは扱わない。 | 安全。並行試行は別 scratch を使い、後発は先発の active row を確認して公開を飛ばす。 |
| cm_detect | `logoframe`、`chapter_exe`、`join_logo_scp` の出力は job ID 固有の `scratch/cm-detect/` 配下に限る。ロゴの一時物を含め media root へ出力しない。 | 完成した CM 範囲と学習結果を DB transaction で保存する。ファイル公開は無い。 | 安全。外部プロセス出力は job scratch に隔離される。 |
| thumbnail | ffmpeg 出力は `MkdirTemp` で作るジョブ固有 scratch。完成物は `.rokuban-media-asset-` stage に file fsync する。 | rel_path lock → transaction → advisory xact lock の下で active row を再確認し、row を予約して stage を rename、親 directory を fsync して commit する。 | 修正済み。canonical を `O_TRUNC` で直接書かない。 |
| seek tiles | 各フレームと合成シートは `MkdirTemp` のジョブ固有 scratch に置く。最後のタイルの再利用も scratch 内のコピーだけで行う。完成シートは `.rokuban-media-asset-` stage に file fsync する。 | thumbnail と同じ rel_path lock、transaction、advisory lock、rename、directory fsync、commit 手順を使う。 | 修正済み。canonical を `O_TRUNC` で直接書かない。 |
| catalog export | Go が export ごとの世代 directory を原子的な `Mkdir` で予約する。同じ export 時刻の同時実行は別名になる。本体を file fsync し、sha256 / サイズ manifest を最後に書いて file fsync する。 | DB 行ではなく、manifest 検証を完成判定に使う。prune は catalog directory 内だけを扱い、最近更新された不完全世代を保持する。 | 安全。予約名の競合と、進行中世代の prune を防ぐ。 |
| catalog rescue | 完成 catalog は検証後に DB transaction で復元する。catalog が無い場合は media root を走査し、既存 file をその場で登録する。rescue は media file を生成・変更しない。 | catalog 経由の復元は snapshot の asset state を upsert し、走査 fallback の `inplace.Register` は file を調べてから DB 行を作る。どちらも delete_reconcile と共通の rel_path lock を取らない。 | 未解決: snapshot より後に削除された file の行を復元する場合と、走査から登録までの間に unlink される場合がある。storage-mutating worker 停止中に実行し、直列化を追跡 issue に分割した。 |
| delete_reconcile | ファイルを生成しない。deleting 状態を記録した後、既知 asset を unlink する。orphan 回収は media root を走査する。 | 既知 asset の削除は rel_path lock を unlink 後の DB 更新まで保持する。orphan は同じ lock と advisory xact lock を取り、live row を再確認してから unlink する。 | 安全。ingest、encode、生成 asset の公開と同じ rel_path lock を使う。 |
| streamer | frame 抽出の ffmpeg は JPEG を stdout に出す。live ffmpeg は session 固有 directory に HLS を出し、`temp_file` を使う。 | media_assets の durable file を公開しない。session の終了時に runtime directory を清掃する。 | media asset 公開契約の対象外。session 間で出力先を共有しない。 |
| ffprobe / config probe | duration や decoder 一覧を stdout で返す。 | 永続 file / DB 公開は無い。 | 対象 file path への副作用なし。 |

### 残る前提

catalog を使う場合も、export 後に削除された asset state を復元する可能性がある。
catalog が無い場合は、走査した file の検査から `inplace.Register` による DB 登録までに
削除が割り込む可能性がある。現状は rescue を storage-mutating worker の停止中に実行する。
rescue と削除の直列化、および両経路の競合テストは追跡 issue に分割した。

thumbnail / seek tiles の公開競合テストでは、rel_path lock を保持して実行する。
lock 中に canonical bytes と active row が変わらず、解放後に完成 bytes とサイズが一緒に公開されることを検証する。
直接 `O_TRUNC` する実装へ戻すと、lock 保持中の bytes assertion が失敗する。
