# 予約の UI

## 予約はワンタップ + トーストから取消

確認ダイアログを挟まない。誤タップは 2 つの手段で緩和する。

- 右端の列は行に対する動作の操作列とし、予約 / 取消 / 放送中のライブを置く。
  行本体（詳細展開）のタップ領域と分離し、各ボタンは最小 44px を確保する
- 実行直後にトーストで「予約しました [取消]」を出す。確認より速く、かつ取り返しがつく

**楽観的更新をする。** 予約 / 取消の結果を対象行へ即時反映し、SSE と REST 再取得で
サーバーの値に追いついたら楽観状態を外す（レベルトリガー）。操作中の行だけを
pending にする（mutation の `isPending` を全行に渡すと、1 件予約する間にリスト
全行のボタンが無効化される）。検索結果の予約ボタンもこの共通経路を使う。

**予約状態を 1 件も取得できていない間は、未予約行の予約操作を止める**。
番組表・検索結果いずれも、予約一覧の取得失敗を番組の表示自体は隠さない。
しかし押せてしまうのが最悪の選択肢になる --- ルール由来の予約に `record` intent を
送ると `program_intents` に手動予約の行が残り、以後ルールが再評価されなく
なっても居座る恒久的な変化になる。古いが既知の値が残っている（初回成功後の
再取得だけが失敗した）間は止めない --- 止めるべきは 1 件も持っていない状態だけ。

**取消にも同じ取り返し手段（トースト + 元に戻す）を対称に置く。** 一覧・
グリッドの取消トーストに「元に戻す」を足す。詳細画面の取消も確認ダイアログ
ではなく Undo にする。

**ただし詳細画面は一覧へ遷移したままにする。** `skip` 意図だけの予約行は
ruler が次パスで削除する。遷移せず留まると、詳細の GET が 404 になってしまう
（旧実装が遷移していたのはこれを避けるためで、正しかった）。`ToastProvider`
はルーティングの外側にある。
だからトースト本体と Undo のクロージャは遷移後も生きており、「遷移はする・
取り消した対象への取り返し手段だけは持たせる」の両立で足りる。

## エンコード設定は予約後に変える

エンコード設定を予約時に聞かない。主操作を 1 タップに保つためで、
「この番組だけ別のエンコードで」の導線は予約成功トーストの「設定」と、
番組リストの展開パネル（予約済みの行だけに出す「予約の設定」）に置く。

予約 intent の直後は ruler が reservations 行を作るまで詳細の GET が 404 に
なりうるが、404 は「まだ無い」と「もう無い」を区別できないので両方で真になる
文言にする。手動リロードは案内しない。行ができ次第 SSE の invalidate で
自動的に表示される。

**Undo は取消の相手（ルール由来 / 手動）で送る intent を変える。** 手動
予約の逆操作は同じ intent を打ち直せば足りる。だがルール由来の予約に同じ
操作をすると「明示的に主張した予約」に変わり、以後ルールがマッチしなく
なっても居座ってしまう。ルール由来の逆操作は、意見を取り下げてルール評価に
戻す別の操作にする。

### 番組リストの操作列はホバー / フォーカスした行だけ立てる

塗りの「予約」を毎行に常時並べると、一等地の画面で中間頻度の操作が地になる。
**行右端の操作列は畳んでおき（幅 0）、ボタンを立てる段になって幅を開く**。
放送中の行では予約ボタンの左にライブボタンも置く:

- 細ポインタ（マウス・トラックパッド）は行の hover / フォーカスで開く
- タッチ / 粗いポインタはホバーが無いので、展開中の行だけ開く
- キーボードは `:focus-visible`（見た目のフォーカスリングを伴うフォーカス）で
  開く。プレーンな `:focus`（マウスクリック / タップの直後に残るフォーカスも
  含む）で開くと、折りたたみ直した直後もその名残りだけで開いたままになる

列を開くと行トグルが縮み、その右端のシェブロンが左へスライドして操作ボタンの
スペースを空ける。放送中の行は予約 80px + ライブ 44px の 124px を目安にし、
その他の行は予約の 80px とする。この 80px / 124px は `box-content` でボタン側の
content box として確保する。開いたときだけ付く `border-l`（1px）はその外側に
足す。`border-box`（既定）のままだと `border-l` がボタン側から 1px 侵食し、
`justify-center` で両端 0.5px ずつ `overflow-hidden` に切られる。したがって
実際に測れる列の外寸（`getBoundingClientRect().width`）は 81px / 125px になる。
以前は列幅を常時確保していたが、ボタンが出ていない間の
空きが不恰好なので畳む方式にした。**代償として横方向はタイトルの truncate
位置が開閉のたびに動く**（実機で確認し、許容と判断）。一方で**縦方向の
レイアウトシフトは避ける** --- ボタンは 44px、行は 56px 以上なので行の高さは
変わらない。そのため番組リストの仮想化（`measureElement`）の再計測を誘発しない。
行の高さが開閉で変わらないことは、e2e `reserve-visibility.mjs` の ①-c が通常行と
放送中の行で実測する。

畳む手段は幅 0 + `overflow-hidden`（`opacity` ではない）。幅 0 の領域は
ヒットテストの標的を持たないので、折りたたみ行の操作列を生座標でタップしても
予約が成立しない。`opacity` は見た目を消すだけでヒットテストも tab 順序も
残すため、「見えないのに実際にはタップできる」標的になり、上記の「行本体と
分離したタップ領域」を自ら壊してしまう（旧実装で実測した欠陥）。

## 予約詳細は base / overrides を 1 画面に統一する

`base`（ruler が書く）と `overrides`（api が書く）は同形の jsonb なので、
ルール由来予約と手動予約を同じ画面で扱える。EPGStation は編集画面が分裂しているが、
その形を最初から避ける。

予約一覧の行に加え、番組リストの行からも来る --- 予約済みの番組行を展開すると
「予約の設定」でここへ遷移する（[programs.md](programs.md) §展開領域の外向き導線）。
overrides の編集はこの画面の担当で、番組行の展開パネル自体は編集欄を持たない。

**機能しないコントロールは置かない。** `encodeProfiles` / `keepOriginal` は
ルール作成/編集と予約 overrides で編集できる。プロファイル一覧は
`GET /api/encode-profiles`（設定名だけ。機微情報なし）。
`keepOriginal: until_encoded` はプロファイル空だとクライアントでも止め、API も 400。
予約 overrides の PATCH は「既存 override + このパッチ + ルールの base」をマージした
実効値で判定する。そのため `keepOriginal` だけを送る・`encodeProfiles` だけを reset
するという、1 リクエストでは見えない組み合わせも、実効値としては空プロファイルなら
弾かれる。
priority は reconciler が mirakc への差分反映（優先度差分での schedules 再作成）を
既に持っているが、編集 UI はまだ無い --- 値は表示のみ。

予約詳細は番組の説明と拡張情報を、題名の塊（題名・局・開始時刻・尺の行、重なり警告）の
下に置く。説明が塊の間に入ると局・時刻が題名から離れ、拡張情報が長い番組では画面外へ
押し出される。EPG 側で番組情報が消えて 404 になった場合はその詳細だけを隠し、予約の状態・
設定は表示し続ける。404 は再試行せず、初回の応答で読み込み中表示ごと消す。予約詳細で文言を
出すのは 5xx だけにする。5xx だけが一時的なサーバー側の失敗を示し、404 以外の 4xx と
ネットワークエラーは利用者に取れる手がなく、詳細を隠すだけでも困らない。この規則は予約詳細
だけのもので、番組一覧・番組表の展開パネルは番組情報そのものが目的なので、どのエラーでも
「番組情報の取得に失敗しました」と出す。
局名・開始時刻・尺の行は番組表へのリンクにする（`at` の扱いは
[programs.md](programs.md) §番組表への `at` 導線）。

取消は詳細ヘッダーの「予約のその他の操作」メニューに置く。破壊的操作は頻度 3 段
（[design.md](design.md) §頻度 3 段）の「端」で、主操作と同格に並べると押し間違いの
面積が増える。確認ダイアログを挟まない代わりに、押した後の取り返しはトーストの「元に戻す」
が持つ（§予約はワンタップ + トーストから取消）。

## ルール一覧から一時停止する

ルール一覧の各行に有効スイッチを置く。無効化だけは確認を挟み、予約一覧のキャッシュから
同じ `ruleId` を持つ `source = rule` の active 予約を数えて、取り消される件数を示す。
`source = manual` の予約はルールにマッチしていても件数に含めず、そのまま残す。

有効なルールの「録画予定 N 件」は、ルール ID が一致する予約すべての `reservationVerdict` を集計し、録画予定と不足時間帯の予約だけを数える。予約一覧の取得前・失敗時は件数を出さず、不足時間帯の件数は容量超過を取得できたときだけ添える。

ルール更新は ruler の評価を早めるヒントであり、予約を同期的には削除しない。
スイッチ更新後に予約一覧を再取得しても、次回評価までは対象予約が残りうる。

「無効」バッジも残す。バッジは一覧を読み流すときの状態表示、スイッチは操作対象であり、
片方だけではもう片方の役割を満たさない。

予約の結論は `lib/reservation-labels.ts` の `reservationVerdict` に集約し、一覧・シリーズ・
詳細・要確認で共有する。評価順は **「録画されず」→「録画しない（重複 / 除外）」→
「録画予定・不足時間帯」→「録画予定」**。`state` enum の訳を結論として表示しない。
`orphaned` は `internal/api/handler.go` の導出どおり、この放送イベントで schedule が一度も
観測されず、録画試行（`recordings` 行）も無かったことを示す。「EPG から消失」ではなく、
「録画が開始されなかった」という意味である。`orphaned` と `skip` が同時に立つ場合も
「録画されず」が優先される。

`skip` の予約は容量需要にならないため、同じ不足区間と交差していても「録画しない」の結論が
優先され、不足の修飾を付けない。`detached` は録画するかを決めない。決めるのは `skip` である。
そのため `detached` を状態バッジにせず、手動 / ルールの出自に「ルール条件外」を添える。
ルール条件を外れたが手動の意図や override が残っている行であることを、結論と区別して読める。

不足区間は、その予約自身の site の時間帯と交差するときだけ既存の `CapacityShortfallBadge`
で補足する。`overages` が未取得・失敗なら不足の修飾を出さず「録画予定」に留める。
これは予定を伝えるだけで、チューナーに収まる保証ではない。
`reservation.programId` は URL の宛先であって利用者が読むフィールドでは
ないので、詳細画面のフィールドとしては出さない。

## 予約詳細 → ルールの導線

「録画 → ルールの導線」（[recordings.md](recordings.md) §録画 → ルールの導線）と
同じ手を予約詳細にも使う。`reservation.ruleId` があるときだけ「ルール」フィールドを
出し、`useListRules()`（パラメータなし = 常に全件）のキャッシュから名前を
引く。同名のルールには `#<id>` を名前に添え、名前が重複していないときは補助ラベルを
付けない。`rules.find` が見つからない間だけ `#N` に落とす。ルール専用の単体取得
（`GET /api/rules/{id}` / `useGetRule`）は使わない。

原則「固有名詞はリンク」に従い、ルールの識別（名前 or `#N`）そのものをリンク
テキストにする。`/rules` に単一ルート（`/rules/{id}`）は無いので、リンク先は
`/search?ruleId=N`（`RulesPage` のルール名リンクと同じ着地先、ルールの
実質的な編集画面）。

## 予約一覧の日付・出自・ルール絞り込み

行のルール名とルール絞り込みは別の操作にする。名前リンクは録画・予約詳細と同じ編集先へ揃え、行内の押せる場所を増やさず、全予約で数えたメニュー件数をルールが広く拾いすぎていないかの点検にも使う。

`ruleId` と `only=attention` は独立した URL 条件にする。ルール選択で `only` を黙って外すと、利用者が選んだ条件が消える。代わりに選択中の要確認チップは 0 件でも残し、どのチップも選ばれない状態を作らない。

行の中身は、行全面リンクより手前に積むためだけに `z-index` を持つ。行 `li` に独立した重なり順（`isolate`）を与えないと、その `z-index` が sticky の日付見出しとヘッダーを越えて描かれる。時刻欄は積まない（積むとタップが行リンクに届かない）。

## 予約一覧をシリーズでまとめる

予約一覧の既定は実効シリーズ表示で、同じ `Reservation.series` の予約を「次に録る回」が早い順にまとめる。ヘッダー右の「シリーズ / 時間順」は同じ `/reservations` 内の端末設定で、`only=attention` と `ruleId` は絞り込んだ後の予約集合に適用する。

表示切替は `rokuban:reservations:group` に保存する（[design.md](design.md) §端末ごとの個人設定）。「時間順」では従来の日付見出し・出自・予約行を保つ。開閉状態は URL と `localStorage` のどちらにも保存しない。

- 1 行は 1 つの実効シリーズ。`series` が null の予約は同じ null 同士でまとめず、題名を名前にして予約ごとに 1 行にする
- 次回候補は `skip=false` の最も早い予約。全件が skip なら最初の予約を出す。「今後 N 本」と結論別バッジの件数は、skip を含む予約行の件数で数える
- 行にはシリーズ名、次回の日時・局・尺・出自、「今後 N 本」、録画されず・重複・除外・不足時間帯の件数を出す。結論バッジを集約し、「ルール外 N」は出さない。色は既存の信号色に揃え、録画しない結論は無彩色にする
- 2 件以上の行は開閉し、各回を日時・シリーズ名を除いた題名・尺・その回のバッジで並べる。各回は予約詳細へのリンク。1 件だけの行は行全体を予約詳細へのリンクにする
- 右端の印は開閉できる行を ∨（開くと ∧）、遷移する行を › にする。同じ › にすると、押して開くのか移るのかを押す前に読めない
- 予約の `site` は行から落とさない。同じ放送を複数サイトで予約していれば各予約を別の 1 本として数える
- 各回の `site` は、複数サイトを構成しているときだけ出す（録画と同じ `shouldShowRecordingSite`。[shell.md](shell.md) §サイトの扱い）。行の予約が 1 サイトでも構成が 2 拠点なら出す。行の予約の `site` 数で決めると、他拠点の予約を消した途端に表示が変わる

シリーズ行の右側は録画ライブラリの状況を示す。`GET /api/recording-shelves` は予約 API と別に取得する。棚との照合は取得が成功しているときだけ行う。非 null の `Reservation.series` と `RecordingShelf.value` を突き合わせ、初回の取得中と失敗の間は箱も「まだ録画なし」の表示も出さない。`value=null` の棚は照合しない。

「棚が無い」と「棚をまだ知らない」は違う。未確認を「無い」と読ませると、録画が溜まっているシリーズを未録画と主張する。一方、再取得中は成功済みの結果を使い続ける。棚は周期と録画の通知で再取得されるので、そのたびに箱を消すと行が組み直される。再取得が失敗すると取得状態が error になるため、古い棚を主張し続けることはない。

一致する棚があれば代表録画のサムネイルと「録画 N 本」「未視聴 M」を出し、0 本は「すべて視聴済み」と表示する。箱とモバイルのメタ情報は代表録画 ID を起点に `/recordings/{id}/series` へリンクする。棚が無い場合はデスクトップでは破線の空枠と「まだ録画なし」を出してリンクを作らず、スマートフォンでは箱を省きメタ情報に文言だけを出す。ハブは録画 id を起点にするので、録画の無いシリーズのハブは作れない。だからリンクにしない。棚の値と代表 ID は予約 API に結合しない。両 API のキャッシュ寿命が異なるためである。

行本体の開閉ボタン・予約詳細リンクはヘッダー領域を覆う層に置く。番組ハブ、出自、容量不足バッジは独立した兄弟要素を手前に置き、対話要素を入れ子にしない。主動作（開閉・予約詳細）は 44×44px 以上、ハブと出自は 24×24px 以上を実ブラウザで測る。展開後の見出しは時間順の日付見出しと同じ CSS 変数を `scroll-margin-top` に使い、sticky なヘッダーの下へ戻す。判定の中身は [web/e2e/README.md](../../web/e2e/README.md) に置く。

## 予約が録られない理由を出す

`skip` が立っている予約は結論バッジで示す。重複排除の判定根拠は詳細の結論文に
「録画しません（重複: 録画 #id・類似度 0.83）」まで出す。この表示は機能の受け入れ条件
そのものとして定めた
（[recording.md](../recording.md) §3.1「なぜスキップされたかを説明可能にする」）。

`skip` は列ではなく `base` + `overrides` + `program_intents.action` からの導出値なので、
API が解決済みの boolean を返す（クライアントで jsonb を合成させない）。

予約一覧・シリーズ行では `reservationVerdict` の結論を 1 つだけ表示する。通常の
「録画予定」は無印、「録画されず」は destructive、「録画しない（重複 / 除外）」は無彩色、
不足時間帯は番組表へのリンクを持つ既存の容量不足バッジで補足する。予約詳細では見出しの
直下に同じ結論を文で出し、「状態」欄は置かない。重複の結論には一致した録画へのリンクと
類似度を含める。

予約行が ruler によって消えた後も、番組表の番組セルと番組リストの番組行は
`intent = 'skip'` を表示する。番組セルは高さ 24px 以上なら「スキップ中」の文字バッジを出し、
24px 未満なら右端の状態マーカーだけを出す。未予約行の右端にある「解除」は
`DELETE .../intent` で意見を取り下げ、ルール評価へ戻す。ルールが番組にマッチしていれば、
次の評価で予約が再び実体化する。overrides がある番組は予約行が残るため、予約一覧の
「録画しない（除外）」結論と詳細説明を使う。
`action = 'record'` が重複判定に勝ったケースでは根拠を残したまま `skip = false` になるため、
「重複と判定したが録る」と表示できる。

### 要確認の絞り込み

予約一覧の見出し下には「すべて（`n`）」と「要確認（`m`）」のチップを置く。
要確認は「録画されず」と不足時間帯の結論を持つ予約である。`detached` だけの予約は含めない。
選択は `?only=attention` に載せ、既定の全件表示は URL に書かない。
要確認が 0 件なら機能しないチップは置かず、URL で指定されている場合は
「確認が要る予約はありません」とだけ表示する。沈黙は録画可能の保証ではないので、緑にはしない。

容量超過 API が未取得または失敗している間は、容量不足を要確認の件数の下界として扱う ---
「録画されず」の分だけで確定できる要確認は出したまま、容量分の判定だけを保留する。
チップと導線は消さない。既定の一覧は表示したまま、容量を確認できず要確認の判定が
不完全であることと再試行ボタンを示す。only=attention ではこの状態で「確認が要る予約は
ありません」と確定しない。再取得に失敗した場合は、キャッシュに残った古い超過区間も
最新の確認結果として使わず、再試行が成功してからバッジと件数を更新する。

容量不足の区間とスキップの理由は行内の結論で読めるようにする。要確認が実運用で 10 件を超えるまで、理由別の絞り込みは足さない。

「録画されず」を出せるのは、放送終了から `epg.retention_grace`（既定 24 時間）までである。
`reservations` は `program_snapshots` の GC とともに CASCADE 削除されるため、それ以降ホームの
要対応から消えても「録れた」保証にはならない。肯定的な「録画漏れはありません」は出さない。

詳細画面の「重複（録画 #id）」は実体への参照なので、その録画単体ページ
（[recordings.md](recordings.md) §録画単体の着地先）へのリンクにする（原則「固有名詞は
リンク」）。この文はどの `Link` にも入れ子にならない位置（詳細画面のフィールド）に
出すので、`<a>` の入れ子の心配は無い。

## 容量不足バッジから番組表へ

一覧の容量不足バッジ（[programs.md](programs.md) §容量超過の帯とバッジ）は「この
時間帯」と言うだけで見る手段が無かった。そこで番組表ルートへの `Link` にする。
ルートは `/programs` である（ホーム新設（[home.md](home.md)）前は `/` だった）。
不足区間の開始時刻は `at`（epoch ms の search param）に積み、表示形式を明示する
`view: 'grid'` も積む。

- **バッジは行本体の詳細リンクの中に置かない。** `<a>` の中に `<a>`（対話コンテンツの
  入れ子）はコンテンツモデル上不正で、**クリックの宛先が不定になる**。「不定」は
  誇張ではなく実測どおりの言葉を選んでいる --- 入れ子のままクリックしたときの宛先は
  viewport 幅で変わり、1280px では外側（詳細ページ）が、375px では内側（バッジの
  番組表リンク）が勝った。同じ DOM 構造で挙動が割れること自体が「宛先を仕様として
  約束できない」ことの証拠であり、これが入れ子を解くべき理由の核心（どちらか一方が
  常に勝つなら、勝つ方を仕様にして済ませる余地があった）
- **解く方向は「行本体をフローから外す」側**。バッジを行本体リンクの外（後続の
  兄弟）へ動かす発想は、実機の幾何を測ると**配置文法を壊す**ことが分かった。
  バッジが chevron の右に出て縦の列が揃わなくなり、モバイル幅では行本体リンクの幅が
  半分以下に減ってタイトルが余計に削られた。壊れていたのは「バッジが行の中にある」
  ことではなく「行本体そのものが子要素を抱えた `<a>` で、バッジという別の対話要素と
  競合する」こと。行の中身（タイトル・バッジ列・chevron）は元の配置のまま通常フローに
  残す。`<li>` を `relative` にして**行本体のリンクだけを `absolute inset-0` の見えない
  全面カバー層**にする（`pages/reservations.tsx`）。容量バッジには
  `position: relative`（z-index は指定しない）を足すだけで、CSS の重ね順
  （positioned な要素は non-positioned な要素より常に上、同じ z-index auto なら
  DOM 順）に乗り、行本体リンクより手前に来てクリックが届く（Bootstrap の
  `stretched-link` と同じ手）。バッジ・行本体、どちらも `<li>` の子で入れ子ではない
- 行本体のリンクは子要素を持たない（`absolute inset-0` の空の `Link`）ため、
  accessible name は `aria-label` で明示する。**採否の基準は「行を一意に識別できる情報か」**
  --- タイトル・局名・時刻・時間・結論は入れる。出自 / 容量バッジの文言は入れない
  （識別情報ではなく、かつ通常フロー要素として残るのでブラウズ（矢印キー走査）では
  読める）。局名を落とすと**同時刻・別局（同名ニュースの裏かぶり）で 2 本のリンク名が
  完全に一致する** --- 「行の中に局名のテキストが居る」ことを見るテストはこの状態でも
  通る。したがって `getByRole('link', { name: ... })` で名前検索そのものを見る
- 副情報の行（局名・時刻・尺・出自・結論・容量バッジ）は **`flex-wrap` で折り返す**。
  折り返さない実装では、360px 幅で長い局名 + 結論バッジが右端の chevron に食い込む
  （`flex items-center gap-2` に戻して再ビルドし実測）。その結果は overflow 37px / 25px、
  子の右端 353 > chevron 左端 328 だった。`recording-row.tsx` / `home.tsx` も同じ形。jsdom は overflow も
  要素の重なりも測れないため、判定は実ブラウザ（`web/e2e/reservations-mobile.mjs`。
  手順は `web/e2e/README.md`）に置く
- **バッジ側の読み上げの規律は変えていない。** `<a>` の accessible name は
  `aria-hidden` な子を無視し `sr-only` な子は含めて計算されるので、外側を `span` から
  `Link` に替えても計算される名前（時刻を主語にした文）は変わらない
- **容量バッジは「予約はワンタップ + トーストから取消」§の 44px の対象外である**。
  冒頭の「行右端の列 + 44px」は行の主動作（予約・取消・再生）に適用する配置文法で
  ある。この容量バッジは行の主動作ではなく、行内テキスト（メタ情報の行）の line-height に
  拘束された inline の見た目を保つ。ただし、見た目を広げるのではなく `::before` を
  24px 高にして実効 hit 寸法を共通下限へ合わせている。`e2e:design` ④-A は visual と
  hit の両方を実ブラウザで測り、この擬似要素と行全面リンクより手前の z-index も
  判定する。44px の用途別基準と全操作標的の 24px 下限は
  [design.md](design.md)「操作標的の寸法は基準を先に決めて実測する」に分けて記録する。
- 着地先（番組表）での `at` の扱いは [programs.md](programs.md) §番組表への `at` 導線
  参照
