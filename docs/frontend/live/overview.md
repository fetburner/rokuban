# ライブ視聴

## 実装方式

ライブ視聴は mirakc のサービスストリームを ffmpeg で HLS に変換して配る。site streamer が入力を読み、セグメントを Pod 内 scratch に書く。セッションはチャンネル単位のインメモリ状態で、idle GC と離脱ヒントを使って回収する。

ライブ URL は site・network ID・service ID から資源を同定し、セッション ID を持たない。録画 HLS は別の置き場単位の経路を使う（[メディア配信](../../api/media.md)）。

## 番組中の録画への切り替え

ライブ画面は、現在番組の録画が進行中で API が世代付き録画 HLS の master URL を返しているとき、「最初から」から録画 HLS へ切り替えられる。再生元は `recording-hls` で、録画 API の `hlsPlayback` にある URL を直接使う。再生位置の指定も同じ録画時間軸に対する seek として処理する。

録画 HLS が利用できないときは、録画再生へ切り替える操作を出さず、ライブ再生を続ける。ライブへ戻る操作は通常のライブ HLS を再び選び、録画再生のセッションを共有しない。

番組表・番組リストからは、対応する録画があればその録画詳細へのリンクを表示する。リンクは録画 ID で作る。クリックだけでは再生を開始せず、録画詳細の表示と明示的な再生操作を分ける。

## 再生位置・音声・速度

ライブの時間軸は番組の予定を示し、録画済みの範囲は録画 API が返す `startedAt` と HLS の有無から示す。録画時間軸の詳細と再生位置保存は [録画再生](../recordings/playback.md) が扱う。

ライブ視聴の音声と画質は同じライブ HLS master 内で選ぶ。録画 HLS へ切り替えたときは録画の master URL と profile に従い、live profile の停滞時自動降格は適用しない。
