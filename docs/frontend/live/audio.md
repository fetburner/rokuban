### 音声・字幕・キー操作

ライブの音声は、標準・主音声・副音声の 3 択で選ぶ。切替はプレイヤーが取る音声トラックを替えるだけである。画質などの切替をまたいで持ち越すのは、字幕の表示と再生中だったかである。音量とミュートは何もしなくても保たれる。

#### 音声の選択肢

音声の選択肢は標準・主音声・副音声の 3 つで、二重音声でない番組でも常に出す。1 ES の通常ステレオで主・副を選ぶと片側だけになる。音声 ES 数はセッション開始時に固定され、次の番組で本数が変わったときの追従は未解決である。

表示名は `標準` / `主音声` / `副音声` で、選択は `?audio=main|sub` に持つ。標準は書かない。

streamer は 3 本の音声レンディションを常に出しているので（[api.md](../../api.md) §音声）、切替はプレイヤーが取るトラックを替えるだけである。プレイリストの取り直しもセッションの作り直しも無く、同じチャンネルを見ている他の視聴者にも影響しない。

streamer はセッション開始時に音声 ES 数を調べる。1 本なら従来どおり L / R を両耳へ写し、複数なら 1 本目を標準 / 主、2 本目を副に使う（[api.md](../../api.md) §音声）。1 ES の通常ステレオで主 / 副を選ぶと、片側だけになる。

ライブの音声 ES 数はセッション開始時に固定する。ffmpeg の map は起動後に変えられないためである。次の番組で本数が変わったときの追従は未解決である（[api.md](../../api.md) §ライブ視聴の HLS）。

<details><summary>根拠</summary>

- 音声 ES 数を調べる手段: ffprobe

</details>

#### 音声トラックの適用

トラックは位置で選び、メインの副作用の依存には音声の選択を入れない。入れると、音声を切り替えるたびに hls.js を作り直すためである。

位置は 0 = 標準 / 1 = 主 / 2 = 副である。適用の API は、hls.js 経路とネイティブ経路で違う。画質の切替などで作り直されたときは、トラック一覧が届いた時点で URL の選択に揃え直す。

チャンネルを切り替えても音声の選択を保つ。一覧のリンクが `?audio=` を運ぶためである。

<details><summary>根拠</summary>

- 位置から取るトラックを決める: `liveAudioTrackIndex`
- 適用の API: hls.js は `audioTrack`、WebKit のネイティブ経路は `video.audioTracks` の `enabled`
- 作り直し後に選択を揃え直す時点: `AUDIO_TRACKS_UPDATED` / `addtrack`
- 副作用の依存に入れない値: `audio`

</details>

#### 音声切替の判定手段

判定は実ブラウザで、ffmpeg が書き続ける実ライブ HLS を相手に行う。Chromium は WebAudio で左右の周波数を測り、主 → 副 → 標準 → 主とそれぞれ聴いてから切り替える。

WebKit は、トラックの有効状態と取得するレンディションを見る。ネイティブ HLS の音は WebAudio に来ないので、鳴っている音は測れない。

<details><summary>根拠</summary>

- 音声切替の判定: `web/e2e/live-audio.mjs`
- WebKit で見るもの: `audioTracks`

</details>

#### 切替をまたいで持ち越すもの

切替を跨いで持ち越すのは、字幕の表示と「再生中だったか」である。後始末の時点でトラックの状態と一時停止の状態を読み、再生中なら再生できる状態になるのを待って再開する（[quality.md](quality.md)「降格のあとは再生を再開する」）。

<details><summary>根拠</summary>

- 読む対象: `<video>` のトラック状態と `paused`、`LivePlayer` の cleanup
- 再開を待つイベント: `canplay`

</details>

#### hls.js が戻す字幕の選択

hls.js は新しいマニフェストを読むと字幕の選択を既定へ戻すので、切替のたびに表示状態を設定し直す。ネイティブ経路は、メタデータが届いた時点で揃え直す。この因果は、実ブラウザで未検証である。

実装を読むと、選択を既定へ戻すのは hls.js のトラック制御で、マニフェストの読み込み開始時にトラックの指定を未選択に戻す。マニフェストの解析が済んだ時点で表示状態を設定し直す。その時点では既定トラックはまだ選ばれていない。解析時の処理はトラック一覧を入れるだけなので、この設定は後の選択のときに、トラックの表示状態を切り替える処理が読む値として効く。

上の因果（hls.js が選択を既定に戻す → 解析時に設定し直す → 後の選択で効く）は、実ブラウザで未検証である。判定手段がまだ無い。

<details><summary>根拠</summary>

- 実装: hls.js 1.7.1 の `SubtitleTrackController.onManifestLoading` が `trackId` を `-1` に戻す。`onManifestParsed` はトラック一覧を入れるだけ。`toggleTrackModes` が設定値を読む
- 設定し直す時点: `MANIFEST_PARSED` で `subtitleDisplay` を設定する
- ネイティブ経路: `loadedmetadata`、`LivePlayer` の cleanup

</details>

#### 音量とミュート

音量とミュートは、持ち越す必要が無い（実測）。動画のソースを外して読み込み直しても、音量もミュートも既定に戻らないためである。守る必要があるのは、切替でプレイヤーを作り直さないことである。

したがって判定が守っているのは、切替でプレイヤーを作り直さないことである。`key={selectedProfile}` を足す変異で、音量・ミュートの両方が失われて判定が落ちることを確認済みである。

判定は実ブラウザ + 実バイナリで行う。jsdom では原理的に測れない 2 点を含む。一覧が遅れて届いてもプレイリストを取り直さないことと、切替で `<video>` が作り直されないことである。この変異では 4 件の NG が出る。遅延到着での取り直し・離脱ヒントが飛ぶ・音量が失われる・ミュートが失われる、の 4 件である。

<details><summary>根拠</summary>

- 後始末の中身と、音量・ミュートを戻さないこと: `removeAttribute('src')`、`load()`、`video.volume`、`video.muted`
- 音量・ミュートが保たれること、変異での落ち方: `web/e2e/live.mjs` の ⑨
- 作り直しを起こす変異: `key={selectedProfile}`

</details>

#### 字幕の持ち越しの実測

字幕の持ち越しは、hls.js 経路とネイティブ経路の 2 方向を実ブラウザで実測してある。字幕を切ったまま、入にしたままのどちらも保たれる。ネイティブ経路は、メタデータの時点で揃えるだけでは足りず、トラックの追加イベントでも適用する。

- hls.js 経路（Chromium）: 利用者が字幕を切ってから画質を切り替えても、表示は切れたままで再表示されない。設定し直す 1 行を外すと、表示に戻る
- ネイティブ経路（WebKit）: 利用者が字幕を入にしてから切り替えても、表示のままである

メタデータの時点で揃えるだけでは足りなかった。実測で非表示に戻ったためである。WebKit はその時点でまだトラックを作っていない。そこで、トラック一覧への追加イベントでも適用している。

WebKit の字幕は既定で非表示である。レンディションに既定の指定を書いても、Safari は利用者が有効にするまで出さない（実測）。したがって 2 方向を見ている。hls.js 経路は「切ったまま」、ネイティブ経路は「入にしたまま」である。

<details><summary>根拠</summary>

- 字幕の持ち越しの判定: `live.mjs` の ⑩
- 設定し直す行: `MANIFEST_PARSED`
- 非表示に戻った状態とその対処: `disabled`、`loadedmetadata`、`TextTrackList` の `addtrack`
- 既定の指定: `DEFAULT=YES`、表示状態の値 `hidden` / `showing`
- 切替の検査点: `mode`

</details>

#### キー操作

ライブでも Space（再生 / 一時停止）・M（ミュート）・F（フルスクリーン）を使える。シークのショートカットと、端末共通の速度設定は、ライブに適用しない。

操作バーに同じボタンがあるので、キー操作も同じにする。

シークのページショートカット（← / →・J / L・0〜9）はライブに適用しない。番組軸は録画の再生時間軸とは別物で、0〜9 の割合シークにも有限の尺が無い。

入力欄・選択欄・リンク・ボタン・編集可能領域・スライダーにフォーカスがある間は、ページショートカットを処理しない。動画要素は除外しない。ネイティブの操作部品を使わない自前の操作バーなので、二重処理は無い。

キー操作の適用表は [recordings/chapters.md](../recordings/chapters.md) §キー操作を参照する。

端末共通の速度設定も、通常のライブには適用しない。ネイティブ HLS の再生速度の指定が実 Safari で有効かは未検証であり、速度変更をライブへ広げる根拠は無い。

<details><summary>根拠</summary>

- スライダーの判定: `[role="slider"]`
- 除外しない動画要素と二重処理の無さ: `<video>`、`controls={false}`
- 再生速度の指定: `playbackRate`

</details>
