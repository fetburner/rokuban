## 録画のブラウザ再生

詳細画面の再生枠にはプレイヤーを 1 つだけ置き、録画の状態から再生元を選ぶ。録画中、または `finished` で `ingest.state` が `pending` / `transferring` の間は、ライブ能力が有効なら追っかけを使う。commit 後は cut でない active な encoded があれば encoded MP4 を使い、無くて live 能力と原本があれば原本 HLS を使う。それらが無ければ active な encoded を使い、さらに無ければ既存の空状態と原本リンクを出す。ごみ箱・失敗・キャンセル状態にはプレイヤーを出さない。再生元を一か所で決めることで、状態ごとに別々の再生面や開始操作を増やさない。

原本と cut 版の両方がある録画では「版」タブから各 encoded を再生できる。原本が残り、live 能力が有効なら同じタブから原本 HLS へ戻れる。cut だけの録画は原本 HLS を既定にして編集できるようにし、比較・確認のため cut 版を選んだ間はチャプター編集を止める。

再生中の録画状態更新だけでは再生元を替えない。版タブで明示的に選んだ原本 HLS は範囲外シークでは選び直さず、新しい offset で張り直す。encoded のプレイヤーは範囲外シークを通知しないので、版タブで選んだ encoded もシークでは替わらない。自動選択の追っかけ・原本 HLS は範囲外シークで選び直す。どちらの選択でも、再生元のエラーと画面の開き直しでは最新の録画状態から選び直し、現在位置を録画開始からの秒で渡す。状態更新のたびに切り替えると録画終了やエンコード完了の通知だけで再生が中断されるため、この切替時機にする。

選び直した結果が今と同じ再生元なら、詳細画面は替えずにプレイヤー自身が張り直す。追っかけは新しい offset のセッション、原本 HLS は新しい offset の playlist で、どちらも同じ `<video>` のまま再生を保つ（`<video>` を作り直すと一時停止する）。全画面も枠を作り直さないので保つはずだが、全画面は未検証。ingest commit 後は新しい追っかけセッションを作れないため、追っかけが入力エラーになったときは REST で録画を取り直して再生元を選び、範囲外のシークも原本 HLS / encoded へ移る。再生元が替わるときは、再生中だったかも持ち越す。カット版 encoded では今再生している `keepRanges` で位置を写す。

切替時の `currentTime` 停止は実ブラウザ E2E で測り、2 秒以下を合格にする。フィクスチャの HLS segment は 2 秒なので、1 segment 分の読み込み余地を認めながら、それ以上続く停止を検出できる。

終端（`ended`）では再生元を選び直さず、終了の状態のまま止める。追っかけの `ENDLIST` は、streamer が録画ファイルの終端まで変換したときにだけ付く（[api/media.md](../../api/media.md) の追っかけの節）。終端は、mirakc が録画終了を返し最後の Range も空だったとき、または record が消えた後に読んだ位置がコミット済み原本の終端と一致したときとする。この判定は壁時計の録画時間（`endedAt - startedAt`）や録画完了取得の前後によらずファイル終端を指すので、移った先に見る続きは無い。壁時計の録画時間と比べて「手前で終わった」と判定すると、真の終端位置を完了後の再生元へ渡し、原本 HLS で範囲外の 416 になりうる。
- 通常の再生元エラーは同じ再生元で張り直し、続けて 2 回までで止めてからエラー表示にする。idle GC で消えた追っかけの再取得もこの経路に含む。
- 追っかけ入力の失敗後、streamer は録画 ID ごとに 10 秒間、新しいセッションの作成を止める。動作中の健全な offset は引き続き共有する。
- 新しいセッションが必要な要求には `502` と `Retry-After` を返す。`Retry-After` 付きの `502` だけを容量不足の `503` と区別して入力失敗とし、同じ再生元を自動で張り直さない。
- 利用者は cooldown 後に「再読み込み」を押せる。idle GC による通常の再取得はこの cooldown に入らない。`Retry-After` の無い `502` はプロキシ由来として、他のエラーと同じく再生元を選び直す。
- 一度も再生していないセッションのエラーでは位置を作らず、保存位置・先頭から・シークで選んだ offset をそのまま持ち越す。0 秒を明示すると保存位置を上書きして先頭から始めるため、0 秒は送らない。

追っかけ・原本 HLS は変換セッションを作るので、詳細を開いただけでは起動しない。通常表示ではポスターと共通の再生ボタンを出し、押した時点で変換を始める。ホームの「録画中」帯や番組表から使う `/recordings/{id}#chase` は「開いたら再生する」直リンクとして残す。encoded MP4 は変換セッションを作らないため、通常の encoded プレイヤーを表示する。画質の設定は元が live profile でも encoded profile でも別名前空間なので、再生元が変わった先ではその側の既定に戻す。

録画中のポスターには保存位置の「続きから」、録画済み時間、予定終端までの録画済み範囲と「先頭から見る」を並べる。保存位置が無いときは「再生」だけを出す（同じ操作を 2 つ並べない）。時間軸は映像と同じ 16:9 の枠の中の下端に重ね、再生の前後で枠の寸法を変えない（枠の外に帯を足すと押した瞬間にページが跳ぶ）。原本 HLS のポスターは視聴済みの操作も枠の中に置く。サムネイルは録画中だと未生成が普通なので、取れなければ画像を外して地を見せる。再生ボタンは押した操作のままプレイヤーを自動再生で始める（`#chase` 直リンクも同じ）。番組の軸は 60 分を超えても合計分で表示する（70 分 12 秒は `70:12`）。録画先端はプレイヤーをマウントせずローカル時計で更新するため、再生前に streamer へ要求を送らない。

active な encoded がある完了録画は **MP4 progressive + Range**。streamer の `GET /api/media/recordings/{id}/file?profile=<name>` を controls の無い `<video>` の src に渡し、映像の下端に自前の再生操作バーを重ねる。原本だけが残る完了録画は streamer の一時 HLS 経路（`/api/sites/{site}/recordings/{id}/original-vod/playlist.m3u8`）でブラウザ再生する。原本自体は MPEG-2 TS のまま読み、変換したファイルは保存しない。encoded MP4 の経路では HLS / hls.js を使わない。原本 HLS の詳細は [api/media.md](../../api/media.md)「録画原本のブラウザ再生」。

- 利用可能な MP4 プロファイルは active な encoded のみとする。操作バーの設定メニューの「画質」に選択肢を置き、サイズがあれば添え、無い資産もプロファイル名を出す。
- 原本だけの完了録画は live の HLS プロファイルで一時変換する。複数あれば同じメニューで画質を選べる。
- 音声は標準 / 主 / 副の 3 択を常にメニューへ出す。切替では選択中の `LivePlayer` の音声トラックだけを変え、playlist と HLS セッションは作り直さない。
- 原本 TS は VLC 等で開けるリンクを残し、プレイヤー内のダウンロードには置かない。
- **再生位置は原本時間軸の ms で保存する。** 追っかけ・原本 HLS・encoded MP4 は同じ録画行の値を共有し、画質プロファイルでは分けない。カット版だけは、再生開始時に固定した keepRanges で原本時間軸と相互変換する。

- 位置は 15 秒ごと、pause / seeked / pagehide で保存し、2 秒未満は削除する。同じページ内の画質切替では video が作り直される。詳細クエリの resumePositionMs は開いた時点の値なので、直前の位置を原本 ms でプレイヤー ref に持ち越し、新しい keepRanges で写して復元する。保存の成否には依存しない。

- 90% 到達の視聴済み PUT が通ったら録画クエリを取り直し、ボタンと未視聴の印を更新する。速度だけは端末ごとの好みなので localStorage に残し、既存の localStorage 位置キーは起動時に削除する。

- 追っかけの offset は `chaseStartByteOffset` による推定値である。原本 HLS・encoded の位置と映像上で一致する精度は**未検証**である。再生元を切り替えた後の原本時間軸はその再生元の時刻で表示するため、切替の瞬間に映像が飛んで見える場合がある。

- 原本 HLS は変換中の EVENT playlist なので、シークできる範囲は変換の先端まで伸びる。endedAt があれば、時間軸の分母は録画ファイル先頭から endedAt までの実尺とする。予定尺 durationMs や変換先端は分母にしない。
- ファイル先頭は max(startedAt, startAt) である。started_at はチューナーを開いた時刻で、ファイル先頭ではない。endedAt が無い録画は予定尺を代用し、分母が 0 ならシークバーは効かない。
- 現在位置は session offset と video.currentTime の和で原本時間軸に直す。現在セッションの offset から seekable 終端までなら同じセッション内で移動し、範囲外は pointer up 時に新しい offset で張り直す。
- 変換済み範囲は seekbar に描かず、変換完了も待たない。範囲はバッファではなく seekable 終端で判定する。WebKit は先端の 3 target duration 手前より先への代入を seekable 終端に丸めるので、その先は張り直す。

- **開始位置は offset 0 や続きから位置が無い場合も明示し、canplay でもう一度設定する。** WebKit の native HLS は明示しないと ENDLIST の無い playlist のライブ端近くから始める。canplay 後に再生すると、受け付けた位置もライブ端へ動く。
- これは自動再開、操作バーの ▶、映像クリック、一時停止中の範囲外 seek 後の ▶ で起きる。再生開始の経路ごとに分けず、セッションを張った後の最初の playing でもう一度明示する。利用者がシークしたら再表明を解除する。
- 再生中に張り直したときは再生を続ける。手動 ▶ の経路では初回 play() の拒否を模擬し、テストから位置を戻さず測る。fixture は 6 segment の EVENT playlist から始まり、待機中は 1 秒ごとに 1 segment 伸びる。

- DB の実尺に基づくシークバーでは末尾付近の offset が映像終端を越え、416 になりうる。エラーにはせず、最後に取れた offset を下限に手前へ丸めて張り直す。
- 続きから再生は「始まる前のシーク」として扱う。保存位置を秒に切り下げた offset のセッションで始め、1 秒未満の端数は startPosition に渡す。
- offset 0 のまま保存位置を渡すと、位置が変換済みの端より先になり、変換待ちになる。25 分先なら J4125 の 4〜6 倍速で 4〜6 分（推定）。
- offset 0 に 4.5 秒を渡した 1 回の測定では、Chromium は端を待ち、WebKit はセッション先頭へ丸めた。fixture の最初の EVENT は 2 秒で、2 秒ごとに伸びる。
- 保存位置より前への巻き戻しは既存の範囲外 seek として扱う。終端を越えた 416 も既存の後退丸めで扱い、端数は捨てる。
- 開始 offset は録画ごとに最初の保存位置で固定する。固定しないと再生中の保存で位置が動くたびにセッションを張り直す。
- 着地は offset の起点と currentTime の和で判定する。操作バーの枠（自動非表示・フォーカス・映像タップ・全画面・PiP）は encoded と同じフックを使う。

- **終端の 90% 到達で視聴済みにするのは ENDLIST 後だけである。** 信号は、hls.js では level details が `live === false` になることと `ended` イベントである。ネイティブ HLS は ENDLIST を直接見られず、`ended` だけを信号にする。

- デスクトップ（`md` 以上）の操作バーは下端の帯 1 本である。シークバーの下の行に、左から再生、前 / 次のチャプター（チャプターがありカット版でないときだけ）、ミュート / 音量、時刻、いまのチャプター名を置く。右には字幕（CC）、視聴済み（✓ のトグル。完了録画だけ）、設定（歯車）、PiP、全画面を置く。シークバーには現在位置のつまみを置き、タイルの下に「時刻 · チャプター名」を出す。バーの色は映像の上で読めるよう固定し（再生済みは白、CM はオレンジ）、ライト / ダークで変えない。PiP は `document.pictureInPictureEnabled` のときだけ出す
- スマホ（`md` 未満）では映像のタップで操作を出す。枠全体を暗くし、中央に前のチャプター / 再生・一時停止 / 次のチャプターを大きく置く。右上に字幕と歯車、下に時刻・チャプター名・✓・全画面・シークバーを置く。
- ミュート / 音量は置かず、PiP は設定シートの行に移す。
- ボタンは 2 組持たず、同じ要素の置き場だけを CSS で変える。状態とアクセシブル名を 1 つに保つ。
- 中央の DOM 順はデスクトップの再生 → 前 → 次にそろえ、スマホの前 → 再生 → 次は `order` で並べ替える。Tab で操作する主なデスクトップでは、見た目とフォーカス順を一致させる WCAG 2.4.3 が効く。スマホに残る不一致は読み上げのスワイプ順にだけ効く。
- タッチで映像を押しても再生 / 一時停止はせず、暗い幕を押すと操作を閉じる。幕は pointerup ではなく click で閉じる。pointerup で消すと続く click が下の `<video>` に届き、再生が止まる。
- `md` 未満でもマウスで幕を押せば、映像のクリックと同じく再生 / 一時停止する。
- 操作バーの右側には、再生できる次のエピソードがあれば「次: 10/1(水)」（▶▶ のアイコン。スマホはアイコンだけ）を置く。次のチャプター（▷|）とは別のアイコンにする。終端カードは映像の上に重ねる（[detail.md](detail.md) §次のエピソードとシリーズ）
- 操作バーの ✓ は固定の名前「視聴済み」と `aria-pressed` のトグルにする。プレイヤー外のボタンは押した後の動作（視聴済みにする / 未視聴に戻す）を名前にする
- 時刻の横にいまのチャプター名を「· 気象情報 ›」の形で出す。区間の隙間は「本編」と出す。名前を押すと、設定メニューと同じ置き場（デスクトップは小窓、スマホは画面下のシート）にチャプター一覧を出す。一覧は「時刻・チャプター名」を時刻順に並べ、いまのチャプターに ✓ を付け、行を押すとその位置へ飛ぶ。全画面は抜けず、全画面中も全画面要素の中に出す。一覧は見るためのもので、編集の操作も編集フォームへの移動も置かない。キー操作は設定メニューと同じで、Esc で閉じると名前のボタンにフォーカスを戻す。設定メニューとは同時に開かない。チャプターが無い録画（カット版を含む）では名前も「›」も出さない（`web/e2e/chapters.mjs` ⑦ ⑧）
- 字幕（CC）ボタンは設定メニューの字幕スイッチと同じ操作の近道で、オンの間は下線を付ける
- **設定メニューは「アイコン・項目名・現在値 ›」の行リストにする**（動画サービスの定石）。基本の行は CM を飛ばす・字幕・再生速度・画質の 4 つで、原本 HLS と追っかけでは音声も加える。2 択はスイッチ、3 択以上は「›」で下の階層に入る。下の階層は同じ枠の中身を「‹ 見出し」と選択肢に差し替え、選択中に ✓ を付ける。プルダウン・ボタンの羅列は使わない（フォームの部品をバーから開くだけでは直感的に操作できない）。選択肢を選ぶとメニューを閉じる
- デスクトップのメニューは映像の上、歯車の真上に半透明の黒い小窓で開き、シークバーを覆わない。スマホのメニューは画面の下からのモーダルのシートで、背後を暗くし、シートは画面の下半分に収める。並びは画質を一番上にし、PiP の行を足す。原本 HLS と追っかけもエンコード版と同じ順にし、音声の行は画質の隣に置く（デスクトップは画質の直前、スマホは直後）。どちらもメニューは全画面要素の内側（プレイヤー枠の中）に描く（外に描くと全画面中に設定を変えられない）。形は `web/e2e/chapters.mjs` ⑦ ⑧ が実ブラウザで測り、原本 HLS の順は `web/e2e/recording-original-vod.mjs` ① が測る
- メニューの行は `menuitem` / `menuitemcheckbox` / `menuitemradio` の役割を持つ。↑ / ↓ / Home / End で見た目の順に行を移り、→ で下の階層へ入る。Esc / ← / 「‹」で 1 段戻り、最上位の Esc で閉じて歯車にフォーカスを戻す。メニューの外を押すと閉じる
- 操作バーを持つのは browser playable な encoded と原本 HLS のプレイヤーである。原本だけが残る完了録画は、live.enabled が有効で HLS 再生できるときにチャプターの目盛り・一覧・CM 自動スキップ・編集 UI も使う。原本 HLS の変換中でも編集できる。境界は録画先頭からの ms で保存し、エディタは固定した録画尺を使うため、変換中に `<video>.duration` が伸びても保存値やエディタの末尾は変わらない。HLS の変換セッションは再生ボタンを押した時点で始め、編集モードに入るだけでは作らない。live.enabled が無効でブラウザ再生できる encoded も無い場合は、チャプターを確認する手段が無い。HLS 再生できない録画・資産が無い録画・ごみ箱では、視聴済み / 未視聴の切り替えをプレイヤーの外に残す
- 再生速度は `ratechange` で `rokuban:playback-rate` に保存し、VOD と追っかけ再生で共有して各 `<video>` の `defaultPlaybackRate` に適用する
- カット版の作り直し案内はプレイヤーの直下、チャプター編集は専用画面に置く。ダウンロードはプレイヤーのメニューに置かない（定石の VOD プレイヤーは設定メニューにダウンロードを置かない）。原本 TS のダウンロード / VLC リンクと版ごとの encoded のダウンロードは、録画詳細の「版」タブに置く
- デスクトップで `<video>` をクリックすると再生 / 一時停止する。停止中、ポインタを動かしてから 3 秒以内、またはバー内に**キーボードフォーカス**（`:focus-visible`）がある間は操作バーを表示する。再生中にポインタが止まって 3 秒経つと隠す。マウスで押したボタンに残ったフォーカスは数えない（数えると再生中ずっと映像に被る）。隠れたバーは `inert` なので、枠内のキー入力（Tab を含む）でバーを出してから処理し、再生中のキーボード利用者が Tab でバーに届くようにする（`web/e2e/chapters.mjs` ⑥）
- 全画面は、映像と操作バーを含む枠を持つ再生グループの要素に要求する（理由は [detail.md](detail.md) §次のエピソードとシリーズ）。ページの `F` キーも同じ経路を通る。要素全画面を持たない iPhone Safari では `video.webkitEnterFullscreen()` に落ちる。その場合は Safari のネイティブ全画面 UI となり、タイルプレビューは出ない。iPhone Safari 実機での再生・全画面確認は未実施であり、Playwright WebKit の結果を実機確認の代わりにしない。未解決: 実機確認は別の issue で追跡する
- 操作バーを表示して字幕が重なるときは、JavaScript が読める WebVTT cue の行をプレイヤー高さと下端の帯（時刻・シークバー）の高さから計算して上げる。スマホの暗い幕は枠全体に敷くので、幕の高さは数えない。native HLS が cue を JavaScript に公開しない WebKit では、この引き上げは何もしない。WebKit はブラウザ既定の字幕位置を画素差分で観測するだけで、実装の検証にはならない。測定は `web/e2e/subtitles.mjs` と `web/e2e/recording-original-vod.mjs` にある
- ライブ視聴（`pages/live.tsx`）・原本 HLS VOD・encoded VOD は同じ自前の操作バーを使う（ライブ側は [live.md](../live.md)）。原本 VOD では変換済み範囲を描かず、画質（複数候補があるとき）と音声を設定メニューに置く
- ページのキー操作は入力欄・選択欄・リンク・ボタン・`role="slider"`・編集可能領域にフォーカスがある間は働かない。video にフォーカスがある場合はページのショートカットを使える。シークバーが `role="slider"` を持ち、← / → を自分で処理するため、グローバルの 10 秒シークと二重処理しない
- 原本 TS 自体を `<video>` の src には渡さない。原本だけの完了録画は streamer が HLS に一時変換し、VLC 等で開く原本リンクも残す
- **シークバーは 1 本だけ**: 操作バー内の seekbar に再生済み割合、チャプターの目盛り、タイルプレビューを描く。マウスを動かすと `/api/media/recordings/{id}/seek-tiles` の該当タイルが seekbar の上に出て、同じ座標計算でクリック / ドラッグした位置へシークする。タイルはサーバー側の固定値（10 秒間隔・10 列）で、`lib/seek-tiles.ts` の純関数が「再生位置 → 格子位置」を出す
- seekbar は `role="slider"`、`aria-valuenow` / `aria-valuetext` を持つ。← / → は 10 秒ずつシークし、Home / End は先頭 / 終端へ移る。タイルの読み込みと位置判定は `web/e2e/seek-tiles.mjs` が実ブラウザで測る
- **プレビューはマウスだけに出す。** タッチでは seekbar のタップ / ドラッグがシークだけに効く。タップには離脱のイベントが来ないので、出すとプレビューが映像を覆ったまま残る
- **プレビューの幅は帯の幅の 4 割まで（上限 320px、16 の倍数に切り捨て）。** 狭い窓で映像の大半を覆わないため。`transform: scale` は文字まで縮めて読めなくするので使わず、タイルの寸法そのものを縮める
- **スマホの配置では時刻の行の上に出す。** 幅 768px 未満ではシークバーが時刻の行の下に来るので、そのままバー直上に出すとラベルが時刻の行に重なる
- **追っかけ再生も同じ操作バーのシークバー 1 本を使う** —— 差し替えるのは軸（番組開始からの経過）と「録画済み / 未録画 / 予定終端」の描画、シーク先の解決だけである（[live.md](../live.md)「録画中の追っかけ再生」）
- **タイルは最初にポインタが触れたときだけ取りに行く。** マウント時に先読みすると、3 時間の録画で 2 MB 程度を、一度もホバーしない利用者にも払わせることになる
- **タイルが無い録画ではプレビューが出ない**（シークバーはシークと再生済み割合のために出る）。未生成・生成失敗・タイル導入前に原本を消した録画がこれに当たる。配信側は未生成なら 404 を返し、クライアントはそれを「プレビューを出さない」として扱う（再生面は壊れない）。ホバーの位置は実ブラウザでしか測れない（jsdom は `getBoundingClientRect()` が常に 0）ので、判定は `web/e2e/seek-tiles.mjs` にある
- **ごみ箱ビューではサムネイル・プレイヤー・原本リンクを一切出さない**。配信側（`GetOriginalMediaAssetForServing` 等）は `recordings.deleted_at IS NOT NULL` を 404 にする契約である（[api.md](../../api.md) §メディア配信）。そのため出しても必ず 404 になる。復元してから見る運用にする。ごみ箱では `encodedAssets` を返さないのも同じ理由（プレイヤーを出さないので揃える必要がない）。**チャプターも取らない**（`GET /api/recordings/{id}/chapters` を発行しない）。プレイヤーを出さない画面でチャプターだけ持っても描く先が無い

### 録画再生で共有する単位と外枠

追っかけと原本 HLS は、録画内のある秒を起点にする HLS セッションである。セッション開始後の offset は両方が使うカスタムフックが持つ。呼び出し元は明示の offset・保存位置・先頭から、のどれで始めるかを渡し、現在位置の報告を受け取る。開始の意図が変わったら新しいセッションとして始める。`pages/live.tsx` は一つの `LivePlayer` のままライブと追っかけを切り替え、詳細画面は `key` で作り直す。どちらも開始意図を渡す形で扱い、親に offset の張り直しを頼む `onChaseOffsetChange` は無くす。これで、追っかけと原本 HLS のセッション外シーク、保存位置からの開始、張り直し後の再生意図を同じ規則にまとめる。

URL の組み立て、セッション起点の写像、範囲終端、416 後の後退丸めは呼び出し元に残す。これらは配信元ごとに異なり、各規則を使う呼び出し元が一つだからである。原本 HLS の起点はフレーム格子へ写し、追っかけは整数秒を使う。追っかけの範囲は伸びるライブ端まで、原本 HLS は固定した録画尺までである。416 後の後退丸めは原本 HLS だけが使う。

再生の外枠は新しいフックを作らず、`usePlayerFrame` に寄せる。ファイル再生は `recording-player.tsx`、原本 HLS・追っかけ・ライブは `live-player.tsx` にあり、どちらも同じ操作バーを出す。再生バーの操作は見た目と対象が同じなので、再生元ごとに分けない。ページキー、全画面対象、字幕 cue の位置、定期・pagehide 保存の共通部分もこのフックに置く。シークの意味と字幕 track の選択は再生元ごとに渡す。キーごとの適用範囲と動作は [chapters.md](chapters.md) §キー操作を唯一の表に置く。

| 振る舞い | ファイル再生 | 原本 HLS | 追っかけ | ライブ |
|---|---|---|---|---|
| F の全画面対象 | 共有の再生グループ | 同左 | 同左 | 同左 |
| ショートカットを無視する要素 | 共通のセレクタ | 同左 | 同左 | 同左 |
| 字幕 cue を操作バーの上へ移す | ○ | ○（WebKit の native HLS は ×） | 同左 | 同左 |
| 字幕として扱うトラックの判定 | 再生元ごとに決める | 同左 | 同左 | 同左 |
| 視聴済みを保存する | ○ | ○ | × | × |
| 再生速度を選べる | ○ | ○ | ○ | × |

- ページショートカットを無視する要素は入力欄・選択欄・リンク・ボタン・編集可能領域・`[role="slider"]` である。`<video>` は除外しない。
- 追っかけでは尺が伸び続けるため、0〜9 の割合シークと視聴済み判定は行わない。追っかけの速度設定は録画再生と共有するが、録画中の WebKit は EVENT playlist を 1 倍に固定し、完了後に保存速度へ戻す。
- 字幕として扱うトラックの判定は再生元ごとに行い、共通化しない。HLS 字幕 track は Chromium と WebKit の両方で `kind="subtitles"` と実測した。
- Chromium は HLS cue の負の `line` と、表示画素の下端が操作バーの上端より上にあることを測る。
- WebKit の native HLS は track を公開するが cue を JavaScript に公開しないため、`cue.line` を書き換える引き上げは効かない。
- 字幕の表示前後のスクリーンショット差分はブラウザ既定の配置の観測であり、実装の検証ではない。そのため NG の判定にはしない。

未解決: WebKit の native HLS では字幕 cue を操作バーの上へ上げられない。上の表で WebKit の native HLS だけ × なのはこのためである。ファイル再生は HLS ではなく `<track>` の WebVTT で、WebKit でも `cue.line` が負になることを `web/e2e/subtitles.mjs` ① で測った。

字幕の位置と全画面対象は jsdom では測れないため、実ブラウザで判定する。

操作バーは `RecordingPlaybackControls` の一つを保ち、`playbackMode` ではなく必要な事実を受け取る。シークバーは時間軸の記述（範囲、使えない区間、印、ホバー表示、シーク可否）を描画する。固定尺・追っかけ・ライブの番組軸はそれぞれの規則を持つ純関数で作る。操作バーは再生速度を変えられるか、音声の選択肢があるかを受け取り、ライブ固有の印・診断・設定名・ボタン配置は呼び出し元が差し込む。`recording-player.tsx` と `live-player.tsx` は同じ操作バーを使うため、シークバーの描画規則は共通にする。3 種の時間軸の作り手はそれぞれ異なる範囲と印を導出するため、一つにまとめない。

<details><summary>根拠</summary>

- 字幕 track と cue の測定: `web/e2e/recording-original-vod.mjs`、`web/e2e/subtitles.mjs`
- ファイル再生の字幕 track と `cue.line`: `web/e2e/subtitles.mjs` ①

</details>

### 視聴状態（続きから・視聴済み）

**再生位置と視聴済みの印は、サーバーに世帯でひとつの値として置く。** 以前の決定「サーバー側視聴履歴は作らない」はこれで覆す。localStorage のままでは、リビングの TV で見始めた続きをスマホで開けない。未視聴の印も端末ごとに食い違い、どちらが正しいかを利用者は判定できない。これは [design.md](../design.md) §個人化の「サーバーへ移す条件」に当たる。Rokuban は利用者を持たないので（[api/deployment.md](../../api/deployment.md) §認証）、値は世帯グローバルで、利用者ごとの表にはしない。

選ばなかった案:

- **localStorage を続ける**: 端末をまたぐ「続きから」を捨てることになり、未視聴の印が端末ごとに食い違う
- **位置はローカル、視聴済みの印だけサーバー**: TV からスマホへの続きが解けない。そのうえ「終端で位置を消し、印を立てる」が 2 つの書き先に割れる

**作るのは再生位置と視聴済みの印の 2 つだけ。** 「いつ何を見たか」の履歴は作らない。「続きから」にも「未視聴」にも要らず、置けば推薦や分析へ用途が広がる。

**2 つは寿命が違うので表を割る**（不変条件 9 / 12）。どちらも `recordings` の衛星表で、書き手は api ロールである。`recordings` を書く watcher / reconciler ではないので本体の列にしない（不変条件 13）。

| | 再生位置 | 視聴済みの印 |
|---|---|---|
| 主キー | `recording_id` | `recording_id` |
| 寿命 | 何度も上書きされ、見終えたら消える | 一度だけ立つ。取り消しは DELETE |
| 行の不在 | 続きが無い | 未視聴 |

見直している録画では両方の行が同時にある。そのため 1 つの状態列にもまとめない。`recordings` の行は本番では DELETE されないので、衛星表の行を掃除する役は作らない。掃除役を足すと 2 人目の書き手になる（不変条件 12）。

#### 再生位置の基準軸は原本の秒

**保存する位置の基準は、非カット版の録画先頭からの経過時間（ms）とする。** プロファイルでは分けない。非カット版はどのプロファイルもこの軸を共有する。原本 HLS はセッションの offset を足し戻してこの軸へ変換する。追っかけも同じ変換を前提にするが、開始点を `-ss` ではなくバイト位置（`chaseStartByteOffset`）で決める別経路なので、下の測定の対象外であり未測定である。カット版の切り出し（`internal/ffargs/cut.go`）は、チャプターの原点を入力の最早 `start_time` とみなして切っている。

ブラウザが報告する `requestVideoFrameCallback` の `mediaTime` は経路ごとに測る。測定には `web/e2e/recording-playback-timeline.mjs` を使う。**期待値は非カット MP4 を ffprobe して得た各目印フレームの PTS** である。チャプターの軸が非カット版の経過時間だからだ。原本 HLS（offset 0 と offset 10 秒）と非カット MP4 をこの期待値と比べる。参考値として、原本 TS の「目印 PTS - 入力全ストリームの最小 `start_time`」との差もログに出す（判定には使わない）。合成 MPEG-2 TS は 30000/1001fps で、音声は映像より 694.011ms 先行する。目印は 10 秒 offset の前後に置く。

原本 HLS は offset を 30000/1001 のフレーム格子へ丸めて `-ss` に渡し、同じ格子上の起点を `mediaTime` に足して録画軸へ戻す。offset 10 秒の実際の起点は 9.976633 秒であり、整数の 10 秒を足すと 23.37ms ずれる。映像出力の B フレームも無効にする。合成 fixture で Chrome + hls.js の表示が 66.73ms 遅れるためである。これらの測定は `web/e2e/recording-playback-timeline.mjs` の目印フレームで行う。

期待値と差の表は（非カット MP4 基準 / 参考: 原本 PTS 基準）である。原本 PTS 基準の差は判定に使わない。

| 経路 | HLS offset 0 | HLS offset 10 | 非カット MP4 |
| --- | ---: | ---: | ---: |
| Playwright Chromium + hls.js | 0.00ms / +6.69ms | 0.00ms / +6.69ms | 0.00ms / +6.69ms |
| WebKit native HLS | 0.00ms / +6.69ms | 0.00ms / +6.69ms | 0.00ms / +6.69ms |

この fixture では両ブラウザの目印フレームすべてが 1ms 以内で一致した。この判定はソフトウェア libx264 の合成 fixture に限り、実録画やハードウェアエンコーダーは未測定である。
- 未解決: 実録画（GR/BS）での同一シーン比較は未測定

- **カット版の秒と原本の秒の変換はクライアントが行う。** 材料はいま再生しているファイルの凍結済み keep 区間（`media_asset_cuts.keep_ranges`）である。カット版を作り直しても、保存される原本の秒はずれない。無効化の規則も要らない
- 主キーに軸やプロファイルを入れる案は採らない。カット版は同じプロファイル名のまま作り直されて時間軸が変わる（上記「カット版」）。名前で分けると古い軸の秒が残り、非カット版どうしでも続きが割れる
- 復元する秒が CM（keep 外）に落ちたときは、次の keep 区間の先頭へ寄せる
- 区間による変換は、字幕の時刻の付け替えとして worker にもある。端の扱い（字幕は捨てる・クリップ、位置は寄せる）は違うが、区分線形の変換そのものは同じ導出である
- 未測定の残差: カット版の区間ごとの半フレーム窓 / ドロップで PTS が飛んだ録画での keep 区間と `currentTime` のずれ / 実録画の GR/BS での同一シーン比較

#### 視聴済みは放送イベントで束ねて読む

**印は押した録画の行 1 つに立てる。読むときは同じ放送イベント `(network_id, service_id, program_start_at)` の全行を束ねる。** どれかに印があれば視聴済みとする。「見た」は録画の行ではなく放送の内容についての事実である。2 拠点で同じ放送を録った場合や、ごみ箱に入れてから録り直した場合に、行ごとに読むと片方だけ未視聴に残る。

- 束ねる母集団は削除済み・supersede 済みの行も含む全行とする。live な行に絞ると、見てからごみ箱へ入れた時点で、もう片方が未視聴に戻る
- 未視聴に戻す操作は、同じ放送イベントの全行の印を消す。押した行だけ消すと、束ねた読みでは視聴済みのまま残る
- 印を他の行へ複製しない。書き手が意図していない行を作ることになる
- **位置は束ねない。** 2 拠点の録画は録画開始の時刻が違うので、原本の軸がずれる。位置は行ごと、印は放送イベントごとという非対称は意図したものである

#### いつ視聴済みにするか

- 終端の 90% に達したら視聴済みにし、その行の位置を消す。閾値は Jellyfin / Plex の既定に倣った。判定はクライアントが `<video>.duration` で行う。api はファイルの実際の長さを知らない
- 90% を超えた後は位置を書かない。書くと見終えた録画が「続きから」に戻る
- **duration が伸びている間は判定しない。** 追っかけ中と、変換中の原本 HLS がこれに当たる。先端の 90% は「見終えた」を意味しない
- 手動の「視聴済みにする / 未視聴に戻す」も置く。他の手段で見た番組に印を付けるためである
- 同じ録画を 2 台で同時に見たときは、後から書いた方が勝つ。世帯スケールなのでガードしない
- **同じプレイヤーの書き込みは、前のものが完了するまで次を送らない。** 先に出した位置 PUT が後から出した視聴済み PUT を追い越すと、視聴済みが消した位置行を PUT が作り直し、見終えた録画が「続きから」に戻る。サーバー側でガードしないのは上の決定のためで、順序はクライアントが守る。pagehide の keepalive は待てないので、この列に載せずに即送る。未完了の書き込みがあれば追い越しうるが、窓は直前の 1 往復だけなので受け入れる

#### 移すもの・移さないもの

- 再生速度とその他の個人設定は localStorage に残す（端末ごとの好みで、事実ではない）
- localStorage にある既存の再生位置は移行しない。見ている途中の録画が一度だけ先頭に戻る
- catalog エクスポートには視聴済みの印を入れ、位置は入れない。印は取り戻せない事実だが、落ちても全件が未視聴に見えるだけで安全側に倒れる。そのため `schemaVersion` は上げない（分類ルールの配列を足したときと同じ扱い。[storage.md](../../storage.md) §8）
