# 番組リストと番組表グリッド

## 全 site の和集合

`/api/sites` の全 site へ番組表を問い合わせ、リスト・グリッドとも結果を和集合として表示する。番組には取得元の `site` を付与し、同じ `programId` が複数 site に存在しても行の identity は `site:programId` で区別する。サービス列も `site:networkId:serviceId` を identity とし、サービス名・予約状態・詳細・予約操作はその site を引き継ぐ。単一 site の列幅・時刻・表示は従来どおりである。複数 site のときは、同一値の共有 BS/CS を見分けられるようグリッドの列ヘッダとリスト行に site 名を表示する。単一 site では site 名を出さない。

容量超過は API が返す `overage.site` を落とさず、対応する site の列領域だけへ重ねる。予約一覧からのバッジは `/programs?view=grid&at=...` に遷移し、番組表が全 site を取得することで第2 site の番組も表示対象になる。

## リストを第一級に置く。グリッドはその上に足す

番組表は本質的にデスクトップ形状（2 次元 × 数十チャンネル × 24 時間）である。グリッドを主・リストを従にすると、モバイルはグリッドの縮小版か単局表示になり、モバイル体験が構造的に犠牲になる。

Rokuban は**リストをモバイルの妥協物ではなく第一級のビューとして設計する**。グリッドは `lg` 以上でのみ出し、モバイルは常にリストのままにする。

グリッドの価値は「見やすさ」ではなく**同時性を空間に符号化すること**であり、このドメインでは同時性がチューナー本数というハード制約に直結する（判定の設計は [data.md](../data.md) §6.5）。

### 実装で決めたこと

座標系は `web/src/lib/epg-grid.ts` の純関数（React 非依存）、グリッド本体は `web/src/components/program-grid.tsx`。

- **セルの高さに下限を設けない。** 5 分番組は 5 分ぶんの高さ（10px）になる。見やすさのために下限を入れると同時性の符号化が崩れ、グリッドの存在理由そのものが失われる
- **短い番組の選択は時間軸のズームで解決する。** 120 / 240 / 480 px/時の 3 段階を端末ごとに保存し、視覚的な高さの下限・隣接セルと重なるヒット領域・hover 専用の選択リストは採らない。どの倍率でも高さ = 放送時間の比例を保つため、5 分番組は 10 / 20 / 40px になる。
- セルが 108px 以上なら 2 行の概要、150px 以上ならジャンル名も出し、未満のセルには時刻と題名以外の本文を足さない。放送終了セルは減光して読み上げ名でも伝えるが、過去番組の詳細を開けるよう `disabled` にはしない。未予約の `skip` はセルの高さで表示を分ける。24px 以上なら「スキップ中」の文字バッジ、24px 未満なら本文のレイアウトを変えない右端マーカーだけを出す。5 分セルを含む短いセルは読み上げと状態マーカーに留める。この閾値は px なので縮尺を上げるほど短い番組にも概要・ジャンル・文字バッジが出る（480px/時なら 15 分番組で概要、30 分番組でジャンル・文字バッジまで出る）
- **列幅はコンテナ幅に追従し、176px から 260px の範囲に収める。** 最小幅は番組名を 2 行で読める幅であり、列数が多く収まらないときは横スクロールを保つ
- **仮想化はライブラリを入れず自前。** 縦軸は連続量で番組セルは目盛りをまたぐ「区間」なので、行の並びを前提とする仮想化ライブラリの模型に乗らない。可視判定は純関数 2 つ（`visibleTimeWindow` / `visibleColumnRange`）に落ちるので、依存を増やすより検証しやすい
- **未計測（DOM 計測が 0）なら全部描く**方向に倒す。jsdom のように計測できない環境で「空のグリッドなのにテストが通る」（CLAUDE.md の「非同期の空虚な成功」の変種）を構造的に防ぐ
- **出し分けは `matchMedia`（JS）で行い、CSS で隠さない。** グリッドが自前のクエリ（全サービス × 24h）と仮想化を持つため。`view` の選択は画面幅で捨てないので、狭くするとリストへ倒れ、広げるとグリッドに戻る
- **容量超過の帯は `ProgramGrid` の `siteOverlay` prop で受ける**。番組セルより上・ヘッダより下の「同一 site の列領域を縦断する層」で受ける（`pointer-events-none`。帯がクリックを飲むと予約操作が壊れる）。`spanToPx(axis, from, to)` を呼べば番組セルと同じ座標に必ず乗る。時間軸列のラベルは `gutterOverlay` に置き、別 site の同時刻ラベルは重ならない位置へ積む。現在時刻インジケータが全体 `overlay` の最初の利用者
- **グリッドの窓は 24 時間を 1 回で取得**する（リストのような窓の積み上げにしない --- 積み途中が「番組がない時間帯」と見分けられない）
- **セルの中に操作を置かない。** 選択した番組は通常ダイアログで開き、リスト専用の `ProgramRow` はマウントしない。リストとダイアログは、同じ予約モデル（時刻・題名・サービス/site・尺・有料・重なり警告）、詳細取得、encode の規則、予約 / 取消 / ライブ / 追っかけの操作意味を共有する。
- ダイアログは、リストのシェブロン・折りたたみ・行区切り・右端幅アニメーションを持たない予約パネルを描く。
- 極小セルに操作をアンカーすると押せない番組ができるため、セルを押した時点で選択済みの番組に操作面を出す。ただし要約直下を横断する帯にはせず、要約行の右側へ置く。
- 通常は予約 / 取消 80px、放送中に再生ボタンを 1 本出すと左に 44px を加えた 124px の固定列とする。`border-l` のため実幅は +1px になる。対応する録画中録画があるときは、同じ再生ボタンのリンク先だけを追っかけへ置き換える。
- 題名を先に読める状態と、開いた直後に 44px 以上の操作へ届く状態を両立する。操作面は詳細より前に置いて本文とスクロールさせる。閉じるボタンはスクロール領域の外へ残し、操作列はその左へ 20px 寄せて重なりを避ける。
- 列は「窓内に番組があるサービス」だけ。順序は種別 → site → リモコン番号 → serviceId → networkId の全順序。site をリモコン番号より上に置くのは、複数 site で地上波のリモコン番号が site をまたいで一致するため（NHK 総合(1) 等）。リモコン番号を先に比べると同じ番号の局が site ごとに 1 列おきへ交互に並び、容量超過の帯（同じ site の連続した列領域に描く）が 1 列ごとの走に分裂する**サービス取得の失敗はグリッドではエラー扱い**（列が構造なので、列 0 本を「番組がない」と区別できない）
- ジャンル色は**補助**。意味の本体は `aria-label` のラベルで、知らないジャンルは「その他」に丸めない（ARIB の本物の「その他」= コード 15 と、分類できなかったことを区別する）。色は Tailwind 標準パレットの 50 / 950 に限定し、未知は既存トークンへ戻す
- **予約済みは見える「予約」と右端の墨の帯で示す。** 輪（`ring`）は選択中だけに残す。予約に同じ `ring-primary` を足すと、ジャンルの左罫・選択中と形が重なり、差が太さだけになる。色は信号のみなので予約にタリー / 琥珀 / destructive は足さない。5 分セル（10px）でも帯が残る（見た目の差は `web/e2e/grid-reserved.mjs` が実画素で見る）

**未検証**: 「全サービス × 24 時間でスクロールが落ちない」は jsdom で計測できないため実ブラウザで確認していない（縦横とも間引く実装は入っている）。受け入れは実機で行う。

リストでは重なりが見えないため、グリッドとは別に画面幅に依存しない伝達手段が必要（後述「容量超過は番組ではなく区間に描く」）。

### 空間的なキーボードナビゲーション

セル間の移動は Tab の直列走査に加えて矢印キーでも行う。形を先に固定して行構造を偽らないため、次の判定基準を採る。

- **ロール**: グリッド全体は名前付きの `role="region"` のままとし、セルは個々の `<button>` の Tab 停止点を維持する。絶対配置で行が整列していないため、`role="grid"` / `gridcell` は使わない。`aria-activedescendant` と roving tabindex も追加しないので、読み上げは従来どおり領域名とセル名を読む
- **起点**: Tab で領域自身に入ったときはセルを自動選択せず、領域の通常のスクロールを維持する。矢印キーを空間移動として扱うのは、個々のセルにフォーカスがあるときだけとする。これで、領域へ入った瞬間に「今のセル」を決める別の規則を持たずに済む
- **上下**: 同じサービス列で開始時刻順に並ぶ前後の番組へ移る。番組間の空き時間は移動先を作らず、次の番組へ進む。番組が重なる場合も区間の交差ではなく開始時刻順の前後を使う。列の端では移動しない
- **左右**: 並び順で隣のサービス列だけを見る。フォーカス中の番組の開始時刻を半開区間 `[startMs, endMs)` に含む番組を優先する。該当しなければ開始時刻の差が最も小さい番組へ移り、同距離なら早く始まる番組を選ぶ。隣列が空、または列の端なら移動しない
- **追従**: 移動先はまず番組データから決める。仮想化で移動先が DOM に無い場合は、時刻軸と列の座標から先に `scrollTop` / `scrollLeft` を合わせ、次の描画でセルを探してフォーカスする。DOM にある場合も可視範囲外なら同じ計算で追従する

この実装では矢印移動で `aria-pressed` の選択状態や選択ダイアログの開閉を変更しない。フォーカスは移動するが、番組の選択・ダイアログ表示は従来どおりセルを押したときだけ行う。**選択ダイアログが開いている間は、矢印キーを押してもグリッドの空間移動は起きない** --- ダイアログはフォーカスをトラップして `document.body` 直下へ portal される。そのためキー入力がグリッドの DOM 部分木を経由しない（実ブラウザで確認済み: `pnpm e2e:grid-navigation` ⑤）。レイアウトと仮想化を含む追従は実ブラウザで判定し、`web/e2e/grid-navigation.mjs` が右移動と仮想化された番組への下移動を確認する。

## グリッドで横スワイプによるナビゲーションを使わない

Android のジェスチャーナビは左右端からの横スワイプが「戻る」なので、グリッドの横パンと確実に喧嘩する。

## 検索条件を番組表に重ねる

ジャンル凡例は条件レンズの入口でもある。押したジャンルは `/programs` の URL に `cond`（`ProgramSearchRequest`）として載せ、検索画面と同じ openapi 検証・`canonicalSearchConditions` を通す。ジャンル以外の条件を含む `/search` からの遷移も同じ値を運び、凡例の近くに条件の要約・一致件数・検索画面へのリンクを出す。詳細条件フォームは番組表に置かない。

一致判定は `POST /api/programs/search` の応答だけから作り、番組と同じ `site:programId` で照合する。検索結果クエリは `programsQueryKeyPrefix` の下に置くため、EPG・予約意図の既存 invalidate で番組データと一緒に取り直される。条件が無いときは検索 API を呼ばない。初回取得中と失敗時は通常の番組表示を保ち、条件チップに状態を出す。確定済みの一致集合はバックグラウンド再取得中も保ち、再取得のたびに淡色や件数を戻さない。取得中に全番組を薄くしたり、失敗を一致 0 件として扱ったりしない。エラーには再試行を付ける。

一致が確定した後も番組を隠さない。非一致セルだけ背景とジャンル色の左罫を中立の地へ戻し、文字・時刻・予約・スキップ・選択表示は残す。一致はセルの `aria-label` にも加える。

一致セルには追加の輪郭を付けない。縦に続く左罫で位置が分かり、選択の輪（`ring-primary`）や予約印（右端の墨の帯）へ同じ意味の輪郭を重ねずに済む。

リストは同時性を表現しないので、条件があるときは一致集合が確定してから非一致を隠す。初回取得中・失敗時は一覧を通常表示のままにする。チップと日付ストリップの件数は検索 API の一致を、選択中のチャンネルがあればそのチャンネルに絞ってから数える（表示される範囲と揃える。判定そのものは検索 API のまま。サービス一覧の取得状態には依存させない）。日付ストリップは番組開始時刻のローカル暦日で数える。日付境界をまたぐ番組も開始日の 1 件として扱い、UTC の日付へずらしたり翌日へ二重計上したりしない。

- 受け入れフィクスチャの RGB 距離: 背景 14.9、ジャンル左罫 139.0

## 番組リスト: 時間順フラット + 日付・サービス絞り込み

- 常に「今」から始まる連続フィード（`pages/programs.tsx`）。上限はどの日付を選んでも共通の「EPG のローリングウィンドウの終端」（8 日先の 0 時）で、24 時で打ち切らない。sticky 日付ヘッダで日付境界を示す
- **API が返す番組を無条件にリストの先頭へ出さない。** API は窓と重なる番組も返すため、読み込んだ最も手前の窓の開始時刻（`listStartMs`）より前に始まった番組が先頭に混ざる。これを見せたままにすると、日付ヘッダと「いま見ている日」の導出が両方とも前日を指す。どちらもリストの先頭の番組から日を決めるためである。この不具合を実機で確認した。`pages/programs.tsx` 側が `lib/program-list.ts` の `filterProgramsFromListStart` で絞ってから `ProgramList` へ渡す。
- `listStartMs` が下限（now を時で切り捨てた時刻）と一致するとき（今日を見ているとき）は絞り込まない。放送中の番組は起点が時刻境界なので、開始が起点より前になりうる。単純に切ると、その番組まで消える。
- **重なり警告は取得済みの予約一覧から導出する。** 行ごとに overlaps API を呼ぶと、仮想化で行が表示されるたび取得が増えるためである。
- `GET /api/reservations` の各行を `site`、`programId`、`state`、`skip`、開始時刻、尺で照合する。同じ site・別番組・`state !== 'orphaned'`・`skip === false` かつ半開区間で重なる予約を表示する。予約状態にかかわらず出し、予約・取消後は一覧を更新する。
- 導出は `useReservationActions` の `overlapsFor` に 1 本化してあり、リストとグリッドの両方が呼ぶ。予約詳細の単一番組だけは従来どおり overlaps API を使う。
- この導出は、サーバー overlaps API の `never_scheduled_events` 単独の述語を近似するものである。never-scheduled 後に録画された放送イベントでは、両者の述語が異なる。
- **仮想化は TanStack Virtual（`useWindowVirtualizer`）を使う**（`components/program-list.tsx`）。グリッドが自前実装を選んだ理由（縦軸が連続量で番組セルが目盛りをまたぐ区間なので、行の並びを前提とする仮想化ライブラリの模型に乗らない）はリストには当てはまらない --- リストは**行の並びそのもの**なので素直に乗る。内側にスクロール容器を持たずページ全体がスクロールするため、`useVirtualizer` ではなく `useWindowVirtualizer` を使う
- 行は `position: absolute` + `transform` ではなく通常のフローに残し、可視範囲の前後を高さぶんのスペーサー（padding）で埋める。sticky な日付ヘッダは通常のフローに乗った要素にしか効かないため。行の高さは `ProgramRow` の段階的開示で可変なので `measureElement` で実測する
- **未計測（DOM 計測が 0）なら全部描く**方向に倒す（`lib/list-virtualization.ts`）。jsdom はレイアウトを計算しないため `measureElement` が常に高さ 0 を読み、動的計測をそのまま使うと可視範囲の計算が壊れる。グリッドの `visibleTimeWindow` / `visibleColumnRange` と同じ「未計測なら間引かない」
- 日付とチャンネルは選択肢の性質が違うので、絞り込みの形も分けている。どちらも横スクロールにはしない --- 3 つの実害がある。単一選択なのに選択中の値が画面外に出て読めなくなること、画面端からの横スワイプが Android のジェスチャーナビの「戻る」と衝突することである（前述「グリッドで横スワイプによるナビゲーションを使わない」と同じ衝突）。さらにヘッダが伸びるとグリッドの高さ予算（`--page-header-height` を引いた残り）が削られる
- **日付ストリップは「いま見ている日」とジャンプ先を分ける。** `dayOffset`（URL の `day` から初期化する state）はタップして跳ぶ先である。ハイライトは可視範囲先頭の番組から導出した「いま見ている日」（`onVisibleDayChange` / `lib/program-list.ts` の純関数）で、ジャンプ先とは別に表示しない。タップ直後は一致するが、スクロール後はハイライトだけが動く。
- 未キャッシュの日へ移る間は前のリストを残し、`ListSkeleton` に置き換えない。置き換えで文書高さが縮んで scrollY がクランプされるのを防ぐ。ジャンプ時はページ先頭へ戻し、プレースホルダ中は前の日の可視範囲から `visibleDay` を更新せず、選んだ日のハイライトを保つ。
- グリッドはスクロールで日をまたがないためジャンプ先をそのままハイライトする。これは押下状態ではないので `aria-current="date"` を使う（`aria-pressed` ではない）。今日のセルは 0 時ではなく「今」から始まるので、`今` という別枠のセルは無い。8 日分で有界なので、横スクロールなしの等幅グリッドに並べて必ず 1 画面に収める。
- 日付ストリップはヘッダのタイトル行の下にフル幅で置く。
- **チャンネル**（`components/channel-picker.tsx` の `ChannelPicker`）が扱う集合は非有界である。候補は「番組を持つサービス」から作る（マルチ編成のないサブサービスは番組を持たないので自動的に消える）。そのため列挙を畳み、現在値を常に表示するトリガーボタン + 開いたときに縦スクロールするポップオーバーにする。トリガーは `PageHeader` のタイトル行右端（`actions`）に置く。**グリッド表示中もトリガーを出したままにする** --- 選択はグリッドの列にも効くので、隠すと解除手段のない 1 列グリッドになる
- チャンネルは**複数選択**（`ChannelPicker` は `Service.id` の `ReadonlySet<number>`。空集合 = すべて）。「見たい局だけをグリッドの列にする」という使い方に直結するため
- チャンネルの行は親子の三状態チェックボックスにする。絞り込みなしでは空集合が「すべて」と全候補のチェック済みを表し、局の行を外すとその局以外の候補 id を `selected` に持つ。「すべて」と種別見出しは、範囲内が全部チェック済みなら外し、一部または全部が外れていれば範囲内をチェックする。種別見出しの操作はその種別の候補だけに適用し、種別が 1 つしかない候補集合では見出しを押せる行にしない。操作後の集合が `ChannelPicker` に渡された `services` の全候補と一致したら空集合へ正準化し、URL に全局の id を並べない
- **0 局はポップオーバー内だけの一時状態**にする。空集合は全局を意味し URL で 0 局を表せないため、全局から「すべて」を外した時点では `onChange` を呼ばない。0 局の間に「1 つ以上選んでください」と表示する。1 局以上選べばその選択を `onChange` し、何も選ばず閉じれば全局へ戻す
- 絞り込み欄に入力中は、「一致したものをすべて」と種別見出しの状態・操作範囲を表示中の候補に限る。検索結果外の局の選択はそのまま保つ
- **サービス絞り込みは `?service=<Service.id>` に置き、日付はローカル暦日の `?day=YYYY-MM-DD` に置く。** service id は複数指定時に OR で扱い、空なら全サービスとする。配列は昇順に正準化し、選択履歴で URL や queryKey を揺らさない。
- `?service=` は複数可・OR で、空集合を `undefined` で表す（`ProgramsPageSearch.service`）。
- 検証は openapi.yaml から生成した zod スキーマ（`src/api/zod.ts`）に委ね、値域や正規表現を手で書き写さない。`lib/url-search.ts` は URL 固有の都合（文字列で届く / 単一値と配列が混ざる / 不正な要素だけ落とす）だけを繋ぐ。
- 選択日は `DayStrip` が出す今日から 8 日間だけを受け取り、範囲外の古い共有 URL は既定の今日に落とす。既定の今日は URL に書かない。日付操作で履歴を汚さず共有 URL を短く保つためである。
- `at` と `day` が矛盾するときは「この瞬間を見る」という要求である `at` の日を優先し、どちらの値も URL から削除しない。
- `view`（表示形式）も URL 状態にしてある。容量不足バッジが `search={{ view: 'grid', at }}` でグリッドを明示するためである。
- URL に `view` が無い素の `/programs` では、端末ごとの `localStorage` に保存した前回値を初期値として使う。URL が常に優先される。ピッカー操作は `replace` で navigate し、1 局ずつ選ぶたびに history を汚さない。
- **絞り込みはサーバー側でかける。** 選択した `Service.id` の配列を `programs.tsx` から渡し、返るのは選択したサービスの番組だけになる。100 サービス規模で無絞り込みの 24 時間ぶんが実測 1.7 MB になり、全件取得してからクライアント側で絞る形は維持できないため
- **ピッカーの候補は `Service.hasPrograms` から作る。** 表示中の（絞り込んだ後の）番組から候補を導くと、1 局に絞った瞬間に候補がその 1 局だけになり、他局へ直接切り替えられなくなる。`hasPrograms` は絞り込みの入力に一切依存しないため、候補集合が絞り込み結果から独立し、この壊れ方が構造的に起きない。グリッドの列は絞り込んだ後の番組（サーバーの返り値そのもの）から導く --- 選んだ局がそのまま列になればよく、独立させる理由が無い
- **ピッカーが実際に表示・列挙できる集合は「候補（`hasPrograms` から作る `filterableServices`）∪ 現在選択中の id」。** 選択は URL から入るため、候補に無い値も無視しない。名前が引けない古いブックマークは `チャンネル #<id>` に落とし、個別に解除できる形を維持する（`pickerServiceDomain`）。同じ `serviceId` の別 network は合成 id が違うので、同じ候補へ潰れない
- sticky な小見出しの `top` はハードコードしない。`PageHeader` が `ResizeObserver` で実測して `--page-header-height` を親要素に書き出す（フィルタ行の増減や文字サイズでずれる）
- **ライブ視聴（`/live`）からは「この局の番組表」で厳密な 1 局へ飛べる。** 番組表と同じ `?service=<Service.id>` の 1 要素配列を使う（1 局のためだけの別形式を持たない）。逆方向（番組表 → ライブ）はページ単位の導線を置かない --- 放送中の番組に「ライブ」ボタンを出す導線は行（`ProgramRow`）単位の担当にする。ページ全体に 2 つ目のライブ導線を足すと、複数チャンネルを絞り込んでいるとき・放送中の番組が絞り込みの外にあるときにどこへ飛ぶかを決める基準が無く、個々の番組から飛べる導線と役割が重複する
- **放送中番組に対応する録画があれば、その番組の再生ボタンだけ追っかけへ切り替える。** 対応判定は番組と録画の site・放送識別値・開始時刻で行う。`programId` と録画 ID は別 identity なので直接比べない。
- リストとグリッドのダイアログは、番組一覧 API が返す optional な `recordingId` を使う。サーバーは番組の `site`・`networkId`・`serviceId`・`eventId`・`startAt` と、録画の同じ識別値を比較する。
- 対応する録画の `status = recording` かつライブ能力が有効な場合だけ、録画詳細の chase（`/recordings/{recordingId}#chase`）へ向ける。対応録画がない場合は `/live` へ向け、能力が無効・未取得・失敗ならボタンを出さない。
- 終了・失敗・キャンセル・ごみ箱の録画は追っかけへ向けない。録画状態の SSE 通知で番組一覧も更新する。

時間窓の継ぎ足し（進行方向の自動読み込み）は [scroll.md](scroll.md)。

## 「既にジャンプ先になっている日」の再タップ

`DayStrip` のタップは `dayOffset`（state）を書き換えて跳ぶ、で足りると思われていたが、**タップした日が既に `dayOffset` と同じ場合**が抜けていた（実機で確認した不具合）。`setDayOffset(同じ値)` は React が再レンダーの理由にしないため、クエリもスクロールも一切動かない。ユーザーはスクロールで「いま見ている日」（`visibleDay`）がジャンプ先から離れていることがあり、その状態での再タップは「その日の先頭へ戻る」ことを期待しているので、`dayOffset` が変わらなくても何かしら起きる必要がある。

- **タップは常にその日へ移動する意味を持つ**。`dayOffset` と一致する場合はクエリの起点を付け替えず、**読み込み済みの `programs` の中からその日の先頭へ `scrollToIndex` する**。呼ぶのは `components/program-list.tsx` の `ProgramListHandle.scrollToDayOffset` で、`virtualizer.scrollToIndex` を直接叩く。対象の添字は `lib/program-list.ts` の `firstIndexForDayOffset`（「可視範囲の先頭 → dayOffset」を導く `visibleDayOffset` と対になる、逆向きの純関数）で引く。見つからなければ（まだ読み込んでいない日）何もしない
- `ProgramList` は `forwardRef` + `useImperativeHandle` で `ref` 経由の命令的 API（`ProgramListHandle`）を公開する。`pages/programs.tsx` はこの `ref` を `selectDay` から呼ぶだけで、`dayOffset` を書き換えるかどうかの分岐は `selectDay` 側が持つ

## 段階的開示

行は「時刻 / タイトル / サービス」だけ。説明の続きと出演者・映像音声属性は展開時に `GET /api/sites/{site}/programs/{programId}` で取る（[api.md](../api.md) の「EPG の読み取り」）。

## 展開領域の外向き導線

行本体（タップで展開）と右端の操作列（予約 / 取消 / 放送中の再生）を分ける（[reservations.md](reservations.md) §予約はワンタップ + トーストから取消）。原則は、**実体へのリンク（「予約の設定」）は展開領域に、行に対する動作（予約 / 取消 / 再生）は右端の操作列に置く**ことである。

`components/program-row.tsx` は次の導線を持つ:

- **放送中**（`startAt <= now < endAt`）の番組: 右端の操作列に 44px のアイコンボタンを予約ボタンの左に置く。対応する録画中録画が無い場合は「ライブで見る」として `/live?service=<Service.id>&site=<site>` へ遷移し、対応する録画の `status = recording` がある場合は同じボタンを「追っかけ再生」として `/recordings/{recordingId}#chase` へ遷移する。`recordingId` は番組一覧 API が返す値をそのまま使う。`live.enabled` が無効なデプロイでは主ナビと同じ判断（`lib/capabilities.ts` の `useLiveEnabled()`）で再生ボタン自体を出さない
- **予約済み**の番組: 展開領域に「予約の設定」 → `/reservations/$site/$programId`。overrides 編集は予約詳細画面の担当で、番組行の展開パネル（未予約時の encodeProfiles / keepOriginal 欄）はここを引き継がない

`now` の判定は「展開されて描画される瞬間（とその後の再レンダー）」で行い、専用の tick タイマーは持たない。このライブ導線は番組 ID を運ばず `networkId` + `serviceId` を渡すため、番組境界を挟んで多少ズレても遷移先を誤らない。遷移先の `/live` 画面が自前で「いま何が流れているか」を再取得するので、真実はそちら側にある。

## 容量超過は番組ではなく区間に描く

チューナー不足の表示は**番組への着色ではなく区間の帯**にする。番組を着色すると「この番組が負ける」という勝敗の主張になるが、決めるのは mirakc であり、Rokuban から見えない消費者（EPGStation の並走・ライブ視聴・EPG 収集）がいるので予測できない。判定と根拠は [data.md](../data.md) §6.5。

- **グリッド（`lg` 以上）**: 超過区間を全チャンネル縦断の帯で着色する。区間は結合済みで返るので描く帯は少ない
- **リスト・予約一覧・モバイル**: 同じ文言のバッジ。グリッドが出ないモバイルでも情報が届く（画面幅に依存しない伝達手段が別に必要、という要件）
- **文言は「この予約は競合しています」ではなく「この時間帯はチューナーが不足しています」。** 主張できるのは下界（超過している）だけで、収まることは保証できない。不足本数と詰まった種別まで出せるので「BS が 1 本不足」と具体的に書く

## 容量超過の帯とバッジ

`web/src/lib/capacity.ts` に交差判定と文言の純関数がある。`components/capacity-band.tsx` はグリッドの `overlay` に渡る帯（色 + 罫線）と `gutterOverlay` に渡る見えるラベルを持つ。`components/capacity-shortfall-badge.tsx` は予約一覧のバッジを持つ。座標は必ず `spanToPx` を通す（番組セルと同じ関数を通すことが「帯とセルが同じ時刻で同じ位置に来る」ことの保証）。

- **肯定的な文言を一切持たない。** 「競合なし」「収まります」は出さない。区間が返らないときは何も言わない（沈黙は保証ではない。[data.md](../data.md) §6.5）
- **複数区間に跨る予約では種別を合併せず、最も不足の大きい区間を採る。** 合併すると「どの区間でも成り立っていない主張」になる
- **見えるラベルは局の列ではなく時間軸列（gutter）に出す。** 帯の内側に出すと、帯の上端が番組セルの上端と重なったときセルの時刻文字と同じ px に描かれる。時間軸列は番組セルを一切置かないので、この列に出す限り衝突しない
- **時間軸列のラベルは自分の内容ぶんの高さしか持たず、帯の上端にアンカーする。** 帯の高さに引き伸ばすと、範囲内の時間軸の目盛りや現在時刻チップまで不透明な地の下に隠してしまう
- **不足区間がちょうど正時に始まると、目盛り（「00:00」等）と同じ位置に来る。** 番組境界は :00 / :30 に落ちることが多く、不足区間の境界も同じ単位なので珍しくない。ラベルはその行を避けて 20px（= 10 分ぶん）下にずれる（`avoidTickRow`）。正時起点では常態で、ほぼ毎回この分岐を通る
- **ただし押し下げても自分の帯の外へは出さない。** 正時起点で、帯の高さが 20px + ラベル自身の高さ 16px = 36px（9〜18 分の帯）未満だと、押し下げた先が自分の帯の下端にはみ出す。はみ出した先は直後に隣接する帯の領域で、そこではその帯のラベルと同じ位置に重なる。この高さを下回るときは見えるラベルを一切描かない。この規則は、正時起点で押し下げた結果の条件に限って適用する。
- **失うものを正直に書く。** この場合、番組表の画面上には種別・本数まで言う手段が残らない。帯の色（琥珀）は BS / GR / CS で同一なので種別を伝えない。予約一覧のバッジは別画面にある。帯自身は `pointer-events-none` の overlay の中にあるので、hover の手がかりも無い。見える範囲では「この区間は何か不足している」までしか分からない。
- もう一方の選択肢（位置をずらして描く）は、隣接する帯のラベルの下に完全に隠れて警告そのものが消える。どちらを選んでも画面上の情報は削られるので、削れない方を消したという判断である。支援技術の利用者は帯の `sr-only`（`shortageRangeMessage`）で、種別・本数・時刻を含む全文を変わらず得られる。
- **時間軸列（56px）は予約一覧のバッジより幅が狭い。** 専用の短い形（`shortageLabelCompact`。「BS-1」）を持つ。バッジの全文（「チューナー不足（BS が 1 本）」）はここでは省略記号で切れて種別も本数も読めなくなる。読み上げ用の全文は帯の `sr-only`（`shortageRangeMessage`）が持つので、見た目だけ削ってよい
- **短縮ラベルには警告アイコンを添える。** 色（琥珀の文字）だけに頼ると、「BS-1」のような短い英数字が日本語 EPG の時間軸列では実在のチャンネル名（NHK BS1 等）と読み違えられうる
- **同一 site 内の不足区間は重ならない**（サーバー側の判定がそう保証する）。全 site の和集合では別 site の区間が同時刻に来るため、帯は同じ site の連続した列領域へクリップし、時間軸列のラベルは重ならない位置へ積む
- **1 site は種別ぶんの列領域（走）を持つ**。`orderServices` は種別（GR → BS → CS → SKY）を最外の tie-breaker に持つため、GR と BS を両方持つ site は列上で非隣接な 2 本の走になる。`ProgramGrid` は走ごとに `siteOverlay` を呼ぶ。帯（見た目）は走ごとに複数出るが、読み上げ文（`sr-only`）は 1 site につき 1 回に絞る（`CapacityBands` の `announce`）。同じ超過区間の説明が走の本数ぶん重複して読み上げられるのを防ぐ
- **帯の帰属（どの site の警告か）は幅制約の無い経路だけに乗せる**。時間軸列は局の列から離れた 1 本の列に複数 site のラベルが積まれるため、複数 site では見た目だけでは帰属が読めない。`shortageLabelCompact`（56px）に site 名を足す余地は実測できていないため、複数 site のときは `shortageLabel` / `shortageRangeMessage` の `showSite` オプションで title（マウス操作者向け native tooltip）と `sr-only`（読み上げ文）にだけ site 名を入れる
- 鮮度は SSE の `reservations` トピックと予約 mutation 後の invalidate に相乗りさせる。容量超過と `program_intents.action` は予約集合・意図からの射影なので、専用トピックを作らない。別タブ・別クライアントの意図変更でも番組表と番組リストを同時に更新する
- **交差判定は予約自身の `site` と突き合わせる。** `Reservation` は `site` を返す。クライアントに定数を持たせないのは、他サイトの不足を自分の不足として出す形で静かに壊れるのを避けるため。フィクスチャが全部 `default` だと定数を書いた実装でもテストが通ってしまうので、**`default` 以外のサイトの予約に自サイトの不足を当てるケース**を置いてある
- **skip / orphaned の予約にもバッジが出る。** サーバーの需要計算はこれらを除外している（= その予約は超過の原因ではない）ので、区間の性質としては真だが因果の誤読を招きうる。フィルタするかは未決

- 予約の site 識別と他 site の誤表示を防ぐ判定: `Reservation`、`site`

## 番組表への `at` 導線

容量不足バッジ（予約一覧。[reservations.md](reservations.md) §容量不足バッジから番組表へ）は番組表ルートへ飛ぶ。ルートは `/programs` である（ホーム新設（[home.md](home.md)）前は `/` だった）。飛び先には `Link` を使い、不足区間の開始時刻は `at` に積む（epoch ms、`lib/programs-search.ts` の `ProgramsPageSearch.at`）。表示形式は `view: 'grid'` に積む（同 `ProgramsPageSearch.view`）。

着地後の反映先は画面幅・表示形式で 3 つに分かれる。**グリッドが唯一「その時間帯」を帯で直接見せられる形なので、それが選べる画面幅ではバッジが `view: 'grid'` を明示する**。

- **`lg` 以上**では `view=grid` でグリッドを開き、`at` を初期スクロール位置に使う（`ProgramGrid` の `scrollToMs`）。表示形式が URL 状態なので、`at` の有無と画面幅から「グリッドにしたい」を推論する必要が無くなった。
- `useMediaQuery` は初回レンダーで `matchMedia` を同期的に読むので、保存した番組表が初回フレームからリストへ倒れない。
- 利用者が手動でリストへ戻すと URL の `view` も `list` に replace されるので、resize だけではグリッドへ戻らない。以前は resize のたびに再評価して自動切替を判定していたが、`view` を URL に持たせたことで「resize で切替を再検討する」という概念自体が無くなり、代わりにリンクを踏むたびグリッドが永続する。
- **`lg` 未満・リスト表示中**: グリッドが無い/選ばれていないので帯を出す手段が無い。次善として「`at` が属する日」への日付ジャンプ（`DayStrip` のジャンプ先）に留める（`lib/day-offset.ts` の `dayOffsetForMs`）。一覧の該当行自体には容量不足バッジ（画面幅に依存しない伝達手段）が出るので、日を合わせれば「その時間帯」に近づける
- 日付ジャンプは表示形式に関わらず効く（グリッド表示中でも `at` の日にジャンプする）

**`at` は URL から消費・削除しない。** 「1 回使ったら `navigate` で消す」実装を試した。しかし `navigate` の非同期解決がグリッドの初回スクロール確定より先に終わり、その結果、初回スクロールが「今」にしか効かなくなる退行を e2e で検出した。**`view` を URL に持たせたことはこの競合を解消していない。**

`at` は URL に残したまま、`scrollToMs`（グリッドへ渡す実際の値）を「いま見ている日が `at` の指す日と一致している間だけ」に条件付ける。実装は `pages/programs.tsx` の `scrollToMs` にある。

「今日」ボタンや日付ストリップで別の日へ移った瞬間に `scrollToMs` は自動的に `undefined`（未指定）へ戻り、以後の軸変更は「今」へスクロールする既定の挙動に戻る。URL を書き換える経路を持たずに同じ保証を得られる。

**グリッドの実際のスクロール位置は jsdom で測れないため、判定手段（`web/e2e/badge-links.mjs`）を実装より先に作った。**

**既知の弱点**: `at` が「今日」の**過去**の時刻（不足区間がもう終わっている等）を指す場合、グリッドは正確な位置へはスクロールしない。`ProgramGrid` の初期スクロールは「軸の範囲内かどうか」しか見ていない。そのため範囲内でも、過去の `at` は現在スクロール中の窓の先頭（`scrollTop = 0`）に落ちる（`components/program-grid.tsx` の `useLayoutEffect` のコメント参照）。容量不足バッジが指す時間帯は通常これから録画される予約の時間帯なので実害は薄いが、精密な位置合わせを主張しない。

**罠**: グリッド上の容量帯（`components/capacity-band.tsx`）は `pointer-events-none`（帯がクリックを飲むと予約操作が壊れる）。リンクにするのはバッジ側だけで、グリッドのオーバーレイには触れない。

<details><summary>根拠</summary>

- バッジ URL と表示形式: `lib/programs-search.ts`、`ProgramsPageSearch.at`、`ProgramsPageSearch.view`

</details>
