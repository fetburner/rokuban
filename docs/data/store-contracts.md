## 9. ドメインごとの store 契約

永続化はドメインごとの interface を通す。**各メソッドが自身のトランザクションを持ち、呼び出し側へ tx を渡さない。**

呼び出し側に tx を渡すと、別々の書き込みを後からまとめてしまい、原子性の境界が契約に表れなくなる。

### 契約の置き場

契約は一つの共通パッケージに置き、ドメインごとに interface と型を定義する。

置き場は `internal/store` とする。今は一つのパッケージに置く。契約を一つの大きな interface にまとめず、ドメインを移すたびに必要な interface を足す。

共通の import 境界を一つに保つことで、移設の途中でも呼び出し側が DB 実装へ依存しない。契約パッケージは pgx と `sqlcgen` を import せず、depguard が境界を検査する。

### メソッドの単位

読み取りは複数のドメインをまたいでもよい。複数ドメインの表を一つのメソッドで書く必要があるときだけ、その書き込みを一つの契約に束ねる。

表の数でメソッドを分けると、原子的であるべき書き込みが呼び出し側へ漏れる。tx を呼び出し側に渡す形も同じ漏れを作る。

### ジョブ投入

ジョブ投入はデータ更新を commit した後のヒントとする。ヒントを失っても、定期 reconcile が永続状態から仕事を見つけ直す。

ジョブ投入まで同じ tx に結び付けると、永続状態の変更と実行基盤の責務が一つの契約に混ざる。

### 方言に依存しない前提

契約は DB 方言による挙動差を前提にしない。

文が失敗したら tx をロールバックしてからエラーを返し、時刻の意味が効く書き込みでは `now` を引数にする。

一意違反は `ErrConflict` に写す。DB 固有のエラーコードを呼び出し側へ漏らすと、別の実装が同じ契約を満たせなくなる。

### チャプター編集

チャプター編集は、状態の読み取り、版を比較した全置換、自動層へ戻す操作を一つのドメイン契約に置く。置き換えとリセットは同じ録画行を先頭でロックし、CM 検出の書き込みと直列化する。

読み取った版を置き換え時に再確認することで、古い下書きが新しい内容を上書きしない。区間の排他制約は不正な重なりを防ぐ最後の境界であり、競合は `ErrConflict` に写す。
